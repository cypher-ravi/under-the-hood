03 · A model is a function

Strip away the mystique and every machine learning model, from a spam filter to a chatbot, is the same kind of thing you write every day: a function that takes inputs and returns an output. The only twist is that some of its numbers are left blank, and the data fills them in.

a · Where we areFrom the table to the thing that reads it

Lesson 02 turned the world into a table: rows of feature vectors x, each with a label y. Today we look at the other half, the model, and say exactly what "learning" does to it.

b · Why this mattersOne idea, from two numbers to billions

When people say a language model "has 175 billion parameters" (that was GPT-3 in 2020), they are describing a function with 175 billion adjustable numbers inside. Once you see a model as a function with knobs, words like weights, training and inference stop being jargon. You will build the smallest possible version today: a function with two knobs, fitted to five flats.

c · The intuitionA recipe with blanks

Picture an old radio. The circuit inside is fixed: someone designed it, and you can't change it. But on the front there are two knobs, tuning and volume. Turn them and the same radio gives very different output. Finding a station means turning the knobs until the sound matches what you want.

A model works the same way.

  • The shape of the function is chosen by a person, like the radio's circuit. "The rent goes up in a straight line with the area" is a shape.
  • The knobs are numbers inside that shape that are left blank. How steep is the line? Where does it start?
  • Learning is turning the knobs until the function's outputs match the answers in the data as closely as possible.

So the programmer still writes code. They write rent = ? × area + ?, and the data fills in the question marks.

d · How it actually worksInputs, knobs, output

You already know what a function is

In code, a function takes inputs and returns an output, and the same inputs always give the same output:

def rent_guess(area):
    return 2 * area + 6

Maths writes the same thing as f(x) = 2x + 6. f is the function's name, x is the input, and the right-hand side says what to compute. Put in x = 4 and you get 2 × 4 + 6 = 14.

Now leave the numbers blank

Replace the 2 and the 6 with letters:

ŷ = f(x) = w · x + b
x: the input
The feature value of one example. Today there is a single feature: a flat's area, in hundreds of square feet (so x = 8 means 800 sq ft).
ŷ ("y-hat"): the prediction
The function's output, its guess. The hat means "estimated". Plain y stays reserved for the true label from the data, here the actual rent in thousands of rupees.
w: the weight
How much the output changes for each unit of input. w = 2 means every extra 100 sq ft adds ₹2,000 to the rent. On a graph it is the slope of the line.
b: the bias
A fixed amount added no matter what. On a graph it is where the line crosses the vertical axis (the value at x = 0). It has nothing to do with "bias" in the sense of unfairness.
Parameters (also: weights)
The knobs together: here w and b. Often written as one symbol, θ (theta), and the model as f(x; θ), read "f of x, given θ".

Each choice of w and b gives a different line. The set of all lines you could get by turning the knobs is called the model family (or hypothesis space). Picking the family is the person's job. Picking the one member of the family that fits best is the computer's job.

Three steps that every ML system follows

  1. Choose a family. "A straight line in the area" is one choice. "Always guess the same number" is a simpler one. A neural network is a much bigger one.
  2. Fit the knobs (training). Score each setting by how far its guesses land from the true labels, and keep the setting with the best score. Today we score by squaring each miss and adding them up, the total squared error. Squaring makes every miss positive and punishes big misses more than small ones. Lesson 07 looks at this choice properly.
  3. Use it (inference). Freeze the knobs. Now the model is an ordinary function: give it a new x and it returns ŷ. The training data is no longer needed.

This was already true in Lesson 02

The spam rule spam if bangs ≥ 3 OR links ≥ 2 is also a function. Its input is a feature vector, its output is 0 or 1, and its knobs are the two thresholds, 3 and 2. Training searched every threshold and kept the pair with the fewest mistakes. Same three steps, different family.

The misses grow from left to right: too low for small flats, far too high for big ones. The line is too steep. So lower the slope and raise the starting point.

Guess 2: w = 2, b = 6. Guesses 14, 18, 22, 26, 30. Misses 0, −1, 0, −2, −1. Squared: 0, 1, 0, 4, 1. Total 6, much better.

Let the computer search. Try every w from 0 to 4 in steps of 0.05 and every b from −10 to 20 in steps of 0.1. That is 81 × 301 = 24,381 settings, each scored the same way. The winner is w = 2.15, b = 5.6, with total squared error 1.90. In words: about ₹5,600 plus ₹2,150 for every 100 sq ft.

Use it. A 900 sq ft flat (x = 9) that was never in the data: 2.15 × 9 + 5.6 = 24.95, so about ₹24,950 a month. The five rows can now be thrown away. Everything the model learned is stored in two numbers.

For comparison, the best constant model guesses the average, 22.8, for every flat, with total squared error 186.8.

# the dataset: 5 flats. x = area in hundreds of sq ft, y = rent in thousands of rupees
X = [4, 6, 8, 10, 12]
Y = [14, 19, 22, 28, 31]

def f(x, w, b):
    """the model: a straight line with two knobs, w (slope) and b (starting value)"""
    return w * x + b

def total_error(w, b):
    """add up (guess - answer) squared over every flat"""
    return sum((f(x, w, b) - y) ** 2 for x, y in zip(X, Y))

print(round(total_error(3, 0), 2))     # 38   first guess
print(round(total_error(2, 6), 2))     # 6    second guess

# "learning": try every knob setting on a grid, keep the one with least error
best = None
for i in range(0, 81):                 # w = 0.00, 0.05, ... 4.00
    for j in range(-100, 201):         # b = -10.0, -9.9, ... 20.0
        w, b = i * 0.05, j / 10
        e = total_error(w, b)
        if best is None or e < best[0]:
            best = (e, w, b)
print(81 * 301, "settings tried")      # 24381 settings tried
e, w, b = best
print(f"best: w = {w:.2f}, b = {b:.1f}, error = {e:.2f}")
# best: w = 2.15, b = 5.6, error = 1.90

# using the trained model on a flat it has never seen: 900 sq ft
print(round(f(9, w, b), 2))            # 24.95

# compare: the best constant model f(x) = b ignores area entirely
mean_y = sum(Y) / len(Y)
print(mean_y, round(sum((mean_y - y) ** 2 for y in Y), 2))   # 22.8 186.8

Trying every setting works for two knobs. It is hopeless for a million knobs: even 10 values per knob would mean 101,000,000 settings. That is why Lessons 05 and 08 build a smarter way to turn the knobs: feel which direction lowers the error, and step that way.

g · Common misconceptionsThree things that sound right but aren't

"In ML, nobody writes the program."A person writes the shape (w · x + b, or a neural network's layout) and the scoring rule. The data only fills in the numbers. Choosing the shape well is a big part of the craft.
"A trained model looks things up in its training data."After training, our model is two numbers, 2.15 and 5.6. The five flats are gone. Large models work the same way: they store parameters, not a copy of the data (though with enough parameters they can memorize pieces of it, which is a known problem).
"Zero error on the data means the best model."The lookup table scores a perfect 0 and can't price a single new flat. The goal is good guesses on examples the model has not seen. Lessons 11 and 12 are about measuring exactly that.

h · Check yourselfThree quick questions

1. Using the trained model ŷ = 2.15x + 5.6, what rent does it predict for a 1,000 sq ft flat? How far off is it from flat D's real rent?

Show answer

x = 10, so 2.15 × 10 + 5.6 = 27.1, about ₹27,100. Flat D's real rent is ₹28,000, so the miss is −0.9 (₹900 too low). Its squared miss, 0.81, is one part of the total 1.90.

2. You add a second feature, number of bedrooms (x₂), to the straight-line model. Write the new function. How many knobs does it have?

Show answer

ŷ = w₁·x₁ + w₂·x₂ + b. Each feature gets its own weight, plus one bias: 3 parameters. With d features a line-shaped model has d + 1 parameters. Lesson 04 shows how to write this compactly with vectors.

3. Which part of the model does training change: the formula w · x + b, or the values of w and b? And which part did a person decide?

Show answer

Training changes only the values of w and b. A person decided the formula (the model family) and how to score a setting (total squared error). If the true relationship were curved, no setting of these two knobs could capture it; you would need a different family.

i · The one-line takeawayIf you remember one thing

A model is a function with adjustable numbers inside; a person picks its shape, and learning is the search for the numbers that make its outputs match the data.

j · Next timeLesson 04 · Vectors and matrices, intuitively

Our line had one input. Real models take hundreds of features and have millions of weights, and writing w₁x₁ + w₂x₂ + … by hand stops working. Vectors and matrices are the notation (and the numpy code) that let one short line describe all of it.
