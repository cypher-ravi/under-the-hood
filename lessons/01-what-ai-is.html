01 · What AI actually is

AI, machine learning and deep learning are three nested ideas, not three names for the same thing. By the end of this page you will be able to say exactly how they differ, and you will have watched a machine "learn" a rule from eight examples.

a · Where we areThe very first step

This is Lesson 01, the start of a 60-lesson path from "what is AI" to transformers and agents, so there is nothing to connect back to yet. Everything later in the course, from gradient descent to transformers, sits inside the map we draw today.

b · Why this mattersEveryone says "AI". Few mean the same thing.

A chess engine from 1997, the spam filter in your Gmail, the face unlock on your phone and ChatGPT are all called "AI". They work in very different ways. As an engineer, knowing which kind of system you are looking at tells you what it needs (rules or data), how it fails, and how you would debug it.

c · The intuitionTwo ways to teach someone to cook

Imagine you want someone to make good dosa batter.

Way one: write the recipe. "Soak 3 cups rice and 1 cup urad dal for 6 hours, grind, add salt, ferment overnight." You, the expert, turned your knowledge into explicit steps. The learner just follows them. If the batter fails in a cold Bangalore winter, you have to notice and add a new rule: "in cold weather, ferment 4 hours longer."

Way two: let them taste. You hand over no recipe. Instead, they make a hundred batches, and after each one you only say "good" or "not good". Slowly they work out the ratios and timings themselves, including the cold-weather adjustment you never told them about, because the failed winter batches taught it.

Way one is classic programming (and early AI). Way two is machine learning. The whole field is about making way two work reliably on a computer.

d · How it actually worksThree nested circles

Artificial intelligence (AI)
The broad goal: getting computers to do tasks that we would call "intelligent" if a person did them, such as playing chess, understanding speech, planning a route or answering a question. AI says nothing about how. The name dates from a 1956 summer workshop at Dartmouth College.
Machine learning (ML)
One way to build AI: instead of writing the rules yourself, you give the computer examples and a procedure that adjusts a program's settings until it does well on those examples. Arthur Samuel, who built a checkers program in the 1950s that improved by playing itself, is usually credited with describing ML as giving computers the ability to learn without being explicitly programmed.
Deep learning (DL)
One family of ML methods, where the program being tuned is a large neural network: many layers of simple arithmetic units stacked on top of each other ("deep" means many layers). It took off around 2012, when a network called AlexNet beat every other method at recognising objects in photos by a wide margin.

The key flip: who writes the rules?

In ordinary programming, you write a function. Data goes in, answers come out, and the logic in the middle is yours. Machine learning flips which parts you supply. You provide data plus the answers you want, and the learning procedure produces the logic.

A little notation, gently

We will use three symbols all course long. Here they are with no scary parts:

  • x is the input: what the system looks at. For a spam filter, maybe "how many exclamation marks are in this email".
  • y is the output or label: the answer. Here, spam (1) or not spam (0).
  • f is the model: a function that turns x into a guess for y. We write the guess as f(x).

A model usually has some adjustable numbers inside it, called parameters. Think of them as knobs. Our toy spam model has one knob, a threshold t:

f(x) = spam      if x ≥ t
f(x) = not spam  otherwise

A human could pick t by gut feel. Learning means picking t automatically, by trying values and keeping the one that makes the fewest mistakes on known examples. That's it. Deep learning is the same idea with millions or billions of knobs and a cleverer way to turn them (Lesson 08, gradient descent), but the shape of the idea never changes:

  1. Choose a model shape with knobs (here: "spam if x ≥ t").
  2. Choose a way to score it (here: count the mistakes).
  3. Adjust the knobs to improve the score on examples.
  4. Use the tuned model on new inputs it has never seen.

e · See itTune the knob yourself

Spam-filter threshold lab

Eight emails, placed by how many "!" they contain. Orange ones are really spam; green ones are real mail. Everything right of the dashed line gets flagged as spam. Slide the line, or press Let it learn to watch the computer try every threshold and keep the best.

mistakes: 2 / 8 accuracy: 75.0% Try a few values. Which one makes the fewest mistakes?

Notice two things. First, no threshold is perfect: email G has only one "!" but is spam. Real data is messy, and the goal is fewest mistakes, not zero. Second, the "learning" was nothing magical. It was a search over knob settings, guided by a score. Keep that picture; it is the heart of the whole course.

f · Worked exampleLearning the threshold by hand

The winner is t = 3 with 1 mistake, so 7 out of 8 correct, which is 87.5% accuracy. Our "trained model" is now the rule spam if the email has 3 or more "!". Nobody wrote the 3; the data chose it.

The same thing in Python, in plain code with no libraries:

# the training examples
x = [0, 1, 0, 2, 3, 5, 1, 4]   # "!" count per email
y = [0, 0, 0, 0, 1, 1, 1, 1]   # 1 = spam, 0 = ok

# the model: one knob, t
def predict(xi, t):
    return 1 if xi >= t else 0

# the score: how many examples it gets wrong
def mistakes(t):
    return sum(predict(xi, t) != yi for xi, yi in zip(x, y))

# "learning": try every knob setting, keep the best
best_t = min(range(0, 7), key=mistakes)
print(best_t, mistakes(best_t))       # 3 1

# use the learned model on a brand-new email with 6 "!"
print(predict(6, best_t))             # 1  (spam)

Trying every value works here because there are only 7 options. With a billion knobs, trying every combination is impossible, which is why later lessons build smarter ways to turn the knobs.

g · Common misconceptionsThree things that sound right but aren't

"AI means ChatGPT."Chatbots are one small corner (the innermost circle). Route planners, fraud detectors and recommendation systems are AI too, and many of them use no neural network at all.
"The model understands, like a person does."A trained model is a function whose knobs were tuned to fit examples. Our spam model "knows" nothing about spam; it only knows that 3 was a good cut-off for these eight emails. Whether huge models develop something like understanding is debated, but mechanically they are still tuned functions.
"Machine learning is always better than writing rules."If you can write the rule exactly (tax brackets, sorting, validating an email address), write it. ML shines when the rule is too fuzzy or too complex to write down, like "is this a photo of a cat?", and when you have lots of good examples.

h · Check yourselfThree quick questions

1. A thermostat that turns on the heater when the temperature drops below 20°C, with 20 set by an engineer. Is that machine learning?

Show answer

No. It has a threshold like our spam model, but a human chose the 20. It becomes ML only if the threshold is picked automatically from data, for example from records of when people felt cold.

2. Put these in order from broadest to narrowest: deep learning, AI, machine learning.

Show answer

AI ⊃ machine learning ⊃ deep learning. Every deep learning system is an ML system, and every ML system is an AI system.

3. In our worked example, suppose email G had 4 "!" instead of 1. What would the best threshold be, and how many mistakes would it make?

Show answer

Now spam emails have counts 3, 5, 4, 4 and ok emails have 0, 1, 0, 2. Any threshold of 3 separates them perfectly: t = 3 gives 0 mistakes (100%). Changing the data changed what the model learned.

i · The one-line takeawayIf you remember one thing

AI is the goal, machine learning is the method of learning rules from examples instead of writing them, and deep learning is machine learning with large neural networks.
