04 · Vectors and matrices, intuitively

A vector is a list of numbers. A matrix is a grid of them. That is almost the whole definition, and with one operation on top, the dot product, you can write any model's prediction for a thousand examples in a single line of code.

Math you'll need
  • M02 · Squares, square roots and absolute value

Rusty on any of these? Each is a short, from-scratch math lesson. Read it first, then come back.

a · Where we areFrom one knob per feature to one line for all of them

Lesson 03 ended with ŷ = w₁·x₁ + w₂·x₂ + b: one weight per feature, plus a bias. Today we give that pattern a name (the dot product), learn the two containers that hold the numbers (vectors and matrices), and see how they turn a loop over every example into one multiplication.

b · Why this mattersThe language every model is written in

Open any ML paper or library and you will see X @ W, "a 768-dimensional embedding", "a weight matrix of shape 4096 × 4096". GPUs became the workhorse of AI largely because they are very good at one job: multiplying big matrices. If you can read shapes and know what a dot product means, most of the code and notation in this course becomes readable.

c · The intuitionA shopping bill

You buy 3 kg of rice, 1 litre of oil and 2 packets of tea. The shop's prices are ₹60, ₹150 and ₹40. Your bill is

3×60 + 1×150 + 2×40 = 180 + 150 + 80 = ₹410
  • Your basket [3, 1, 2] is a vector: a list of numbers in an agreed order (rice, oil, tea).
  • The price list [60, 150, 40] is another vector, in the same order.
  • "Multiply matching entries, then add" is the dot product. It squeezes two lists into one number.
  • Now imagine the shopkeeper with a notebook of 100 customers, one basket per row. That notebook is a matrix. Running the price list down every row gives 100 bills at once: that is a matrix times a vector.

A model's prediction is exactly this bill. The features are the basket, the weights are the price list, and the bias is a fixed delivery charge.

d · How it actually worksFour ideas, in order

1. Vectors: one example as a list

In Lesson 02 each row of the table was a feature vector. Take a flat with 800 sq ft (written 8, in hundreds) and 2 bedrooms:

x = [8, 2]
Entry (or component)
One number in the list. Maths writes x₁ = 8, x₂ = 2 (counting from 1). Python writes x[0] and x[1] (counting from 0). Same thing.
Dimension
How many entries the vector has. [8, 2] is 2-dimensional. A word embedding in a language model might have 768 or more. The rules below never change with the size.
Bold letters
Books often write vectors in bold (x, w) and plain numbers, called scalars, in normal type (b). Here we use plain code font for both and say which is which.

A 2-dimensional vector can be drawn as an arrow from the origin to the point (8, 2). With 768 entries you can't draw it, but the arrow picture still guides intuition: length, direction and angle all keep their meaning.

2. Two things you can do to vectors

Add them entry by entry: [3, 1] + [1, 2] = [4, 3]. As arrows, put the second one's tail on the first one's tip. Scale them by multiplying every entry by one number: 2 × [3, 1] = [6, 2], the same direction, twice as long. Both need vectors of the same dimension; adding [3, 1] to [1, 2, 5] has no meaning.

3. The dot product: two lists in, one number out

w · x = w₁x₁ + w₂x₂ + … + wₙxₙ

Multiply matching entries and add them up. Small version: [3, 1] · [1, 2] = 3×1 + 1×2 = 5. With it, Lesson 03's model becomes

ŷ = w · x + b

which looks like the one-feature line from last time but now works for any number of features. With w = [2, 1.5] (₹2,000 per 100 sq ft, ₹1,500 per bedroom) and b = 4, our flat gets 2×8 + 1.5×2 + 4 = 23, so ₹23,000 a month.

The dot product also has a geometric meaning, which matters a lot from Lesson 30 onward:

w · x = |w| × |x| × cos(angle between them)

|x| is the vector's length, √(x₁² + x₂² + …), Pythagoras extended to more entries. The cosine is 1 when the arrows point the same way, 0 when they are at right angles, and −1 when they point opposite ways. So a large positive dot product means "these two point in a similar direction". That is how a search engine can measure whether two pieces of text mean similar things, once each is turned into a vector.

4. Matrices: many examples at once

Stack the feature vectors of four flats as rows and you get a matrix, a grid of numbers:

area x₁bedrooms x₂
A41
B62
C82
D103
Shape
Rows × columns, always in that order. This matrix, called X, is 4 × 2: 4 examples, 2 features. In ML, the convention is one row per example and one column per feature.
Matrix × vector
X w means: take the dot product of each row of X with w. Four rows in, four numbers out. Add b to each and you have every prediction: ŷ = X w + b.
The shape rule
A dot product needs equal lengths, so the number of columns of X must equal the length of w. (4 × 2) times (2) gives (4). In general (m × n) times (n × p) gives (m × p): the inner numbers must match and disappear, the outer ones survive. Most shape errors in ML code are this rule being broken.
Transpose
Xᵀ (numpy: X.T) flips rows and columns, turning 4 × 2 into 2 × 4. You will see it constantly when lining up shapes.

Multiplying a matrix by a matrix is the same idea repeated: each column of the second matrix is its own weight vector. If a model predicted both rent and maintenance, W would be 2 × 2 (one column per output), and X W would be 4 × 2: two predictions per flat, still one line.

f · Worked exampleBy hand, then in numpy

Vector basics with u = [3, 1] and v = [1, 2]:

  • u + v = [3+1, 1+2] = [4, 3]
  • 2u = [6, 2]
  • u · v = 3×1 + 1×2 = 5
  • |u| = √(9 + 1) = √10 ≈ 3.162 and |v| = √(1 + 4) = √5 ≈ 2.236
  • cos = 5 / (3.162 × 2.236) = 5 / 7.071 ≈ 0.707, which is the cosine of 45°.

Pricing four flats with w = [2, 1.5], b = 4:

Flatrow of Xrow · w+ bŷ
A[4, 1]8 + 1.5 = 9.5+413.5
B[6, 2]12 + 3 = 15+419
C[8, 2]16 + 3 = 19+423
D[10, 3]20 + 4.5 = 24.5+428.5

In numpy, a vector and a matrix are both np.array. The @ operator is matrix multiplication (and the dot product, for two vectors). Plain * is something else, as the third line shows.

import numpy as np

# vectors: one flat = [area in hundreds of sq ft, bedrooms]
u = np.array([3, 1])
v = np.array([1, 2])
print(u + v)          # [4 3]
print(2 * u)          # [6 2]
print(u * v)          # [3 2]   element-wise, NOT the dot product
print(u @ v)          # 5       dot product: 3*1 + 1*2
print(round(np.linalg.norm(u), 3), round(np.linalg.norm(v), 3))   # 3.162 2.236
cos = (u @ v) / (np.linalg.norm(u) * np.linalg.norm(v))
print(round(cos, 3), round(np.degrees(np.arccos(cos)), 1))        # 0.707 45.0

# a matrix: 4 flats (rows) x 2 features (columns)
X = np.array([[4, 1],
              [6, 2],
              [8, 2],
              [10, 3]])
w = np.array([2, 1.5])  # per 100 sq ft, per bedroom (thousands of rupees)
b = 4                   # base rent
print(X.shape, w.shape) # (4, 2) (2,)

# the slow way: a loop of dot products, one per flat
print([float(row @ w + b) for row in X])   # [13.5, 19.0, 23.0, 28.5]
# the matrix way: every flat priced in one line
y_hat = X @ w + b
print(y_hat, y_hat.shape)                  # [13.5 19.  23.  28.5] (4,)

try:
    w @ X               # shapes (2,) and (4, 2) don't line up
except ValueError as e:
    print("ValueError:", str(e)[:60])
# ValueError: matmul: Input operand 1 has a mismatch in its core dimension
print(X.T.shape)        # (2, 4)  transpose flips rows and columns

The loop and X @ w + b give identical numbers. The difference is that numpy runs the matrix version in optimized compiled code, and on a GPU thousands of those multiply-adds happen in parallel. Training a neural network is, to a large degree, doing this over and over with much bigger matrices.

g · Common misconceptionsThree things that sound right but aren't

"Vectors are arrows from physics, so they only make sense in 2D or 3D."In ML a vector is just an ordered list, and 768 entries is as valid as 2. Length, angle and dot product are all defined by the same formulas in any dimension; only the drawing stops working.
"Multiplying two vectors means multiplying entry by entry."That is the element-wise product, u * v = [3, 2], still a vector. The dot product, u @ v = 5, multiplies and then adds, giving one number. Mixing up * and @ is a classic numpy bug, and it often runs without an error because numpy happily broadcasts shapes.
"Order doesn't matter, like with ordinary multiplication."X @ w works and w @ X raises an error, because shapes must line up in that order. For matrices in general, A @ B and B @ A are usually different, or one of them isn't even defined.

h · Check yourselfThree quick questions

1. Compute [2, −1, 3] · [4, 0, 1].

Show answer

2×4 + (−1)×0 + 3×1 = 8 + 0 + 3 = 11.

2. A dataset has 1,000 examples and 20 features. What is the shape of X, how long must w be, and what shape is X @ w?

Show answer

X is 1000 × 20 (one row per example). w needs 20 entries, one per feature column. X @ w has shape (1000,): one prediction per example. If w had 19 entries, numpy would raise a shape error.

3. What is [2, 1] · [−1, 2], and what does that tell you about the two arrows?

Show answer

2×(−1) + 1×2 = 0. A dot product of zero (with neither vector being all zeros) means the arrows are at a right angle. In ML language, the two vectors share nothing in common direction; later, with embeddings, that will read as "unrelated".

i · The one-line takeawayIf you remember one thing

An example is a vector, a dataset is a matrix, and a linear model's prediction for every example is one matrix–vector product: ŷ = X w + b.
