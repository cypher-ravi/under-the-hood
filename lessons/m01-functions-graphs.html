M01 · Functions and graphs

A function is a rule that turns an input into an output, exactly like a small piece of code with no side effects. A graph is that rule drawn as a picture: every input paired with its output, plotted as a dot. With those two ideas, "a model is a straight line with two knobs" stops being abstract.

a · Where this is usedThe AI lessons that lean on this page

b · Why this mattersEvery model is one of these

A spam filter, a rent predictor and a chatbot are all functions: features go in, a prediction comes out. Training means changing a few numbers inside the rule, and the clearest way to see what those numbers do is to draw the function and watch the picture move. If you can read f(x) = 2.15x + 5.6 and picture its line, you can follow Lesson 03 and Lesson 05 without stopping.

c · The intuitionA vending machine

Think of a vending machine. You press a button (the input), the machine follows its wiring (the rule), and a snack drops out (the output). Two things make it trustworthy:

  • Same button, same snack. Press B4 today or next week and you get the same thing. If B4 sometimes gave crisps and sometimes gave a drink, you could not rely on it.
  • One snack per press. Each button gives exactly one thing. Two different buttons may give the same snack, though, and that's fine.

That is all a function is. As a programmer you already write them:

def rent_guess(area):
    return 2 * area + 6

Call rent_guess(4) a thousand times and you get 14 every time. It doesn't print, doesn't read a file, doesn't change a global variable: it only turns an input into an output. Maths calls this kind of thing a function, and it only ever means this pure kind.

Now imagine you pressed every button and wrote each (button, snack) pair on a card, then pinned all the cards on a wall in order. That wall is the graph. It shows you the whole machine at once, so you can spot patterns, like "the further right you go, the bigger the snack".

d · How it actually worksEight small steps, from a rule to a line to a curve

1. The notation f(x)

Maths writes the code above as one line:

f(x) = 2x + 6
f
The function's name, like rent_guess. Any letter works; f is short for "function", and g, h are common second choices.
x
The input, like the parameter area. It is a placeholder: a blank to be filled with a number.
f(x), read "f of x"
The output you get when you feed x into f. The brackets mean "applied to", not multiply. It is a function call.
2x
"2 times x". In maths, a number written right next to a letter means multiply, so 2x is 2 * x in code. The dot in w · x means the same thing.

2. Plugging in a value

To evaluate a function at a number, replace every x on the right-hand side with that number and work it out. For Lesson 03's flat C, which is 800 sq ft, so x = 8 (area in hundreds of sq ft):

f(8) = 2 × 8 + 6 = 16 + 6 = 22

The answer is a rent of 22, meaning ₹22,000 a month. Do it for all five flats and you get a table of values:

3. The graph: every (input, output) pair as a dot

Axes
Two number lines at right angles. The horizontal axis (the x-axis) holds inputs, growing to the right. The vertical axis (the y-axis) holds outputs, growing upwards. They meet at the origin, the point where both are 0.
A point (a, c)
A pair of numbers written in brackets, input first. To plot (8, 22): walk 8 to the right, then 22 up, and put a dot. Order matters: (22, 8) is a different place.
y = f(x)
We name the output y, so each dot sits at (x, y) with y = f(x). That is why people write y = 2x + 6 and f(x) = 2x + 6 interchangeably.

Plot the five rows of the table and you get five dots: (4, 14), (6, 18), (8, 22), (10, 26), (12, 30). They line up perfectly. Now fill in the gaps: f(5) = 16, f(7) = 20, f(9) = 24, even f(8.5) = 23. Every new input adds a new dot on the same straight path. Plot every possible input and the dots merge into a solid line. The graph is the set of all the dots, so a line on a graph is really infinitely many (input, output) pairs packed tight.

4. Reading a graph both ways

  • Forwards (input to output). Find your x on the horizontal axis, go straight up until you hit the line, then go straight across to the vertical axis and read off y. That is evaluating f with your eyes.
  • Backwards (output to input). Start with a y you want, go across to the line, then down to read x. "Which flat size would this model price at ₹22,000?" Across from 22, down to 8. With algebra: 2x + 6 = 22, so 2x = 16, so x = 8.

Forwards always gives exactly one answer, because a function gives one output per input. Backwards might give one answer, none, or several. We'll meet a function with two answers in step 8.

5. The straight line y = w·x + b

Swap the 2 and the 6 for letters and you have the shape Lesson 03 uses for its model:

y = w · x + b
w: the slope (in ML, the weight)
How much y goes up when x goes up by 1. Measured as rise over run: pick two points on the line, divide the change in height (rise) by the change in input (run). For 2x + 6 from (4, 14) to (12, 30): rise 30 − 14 = 16, run 12 − 4 = 8, slope 16 ÷ 8 = 2.
b: the intercept (in ML, the bias)
Where the line crosses the vertical axis. On that axis x = 0, and w · 0 + b = b, so the crossing point is always (0, b). For 2x + 6 it is (0, 6).

Why is the slope the same everywhere on a line? Look at the table in step 2. Each time x grows by 2, the output grows by 4: 14, 18, 22, 26, 30. That's no accident. Going from x to x + 1 changes w·x + b into w·x + w + b: exactly w more, whatever x you started from. Equal steps in, equal steps out. That constant step is what makes the dots line up straight, and it's why one number, w, can describe the steepness of the whole line.

School books often write the same line as y = mx + c or y = mx + b. Only the letters differ. ML uses w for "weight" because it says how much weight the input gets.

6. What turning w does: tilt

  • Bigger w: steeper line. Each 100 sq ft adds more rent.
  • w = 0: a flat line, y = b for every input. The model ignores x entirely (Lesson 03's "constant" family).
  • Negative w: the line goes downhill. Bigger inputs give smaller outputs, like "older car, lower price".

Changing w alone spins the line around its crossing point (0, b), because that point doesn't depend on w. Notice that the effect grows with x: adding 0.1 to w raises f(4) by 0.4 but f(12) by 1.2.

7. What turning b does: slide

Changing b adds the same amount to every output, so the whole line moves straight up or down without tilting. 2x + 6 and 2x + 12 are parallel: same steepness, one sitting 6 higher. Together, w sets the tilt and b sets the height, and between them they can produce any straight line (except a perfectly vertical one, which isn't a function: one input would need infinitely many outputs).

8. A first curve: f(x) = x²

Not every function is a line. Take f(x) = x², read "x squared", meaning x × x (in Python, x ** 2). Plug in a few values:

x−3−2−10123
x²9410149

Two things are different from a line:

  • The steps aren't equal. From 0 to 1 to 2 to 3, the outputs climb by 1, then 3, then 5. The rise per step keeps growing, so the dots bend into a U shape (a parabola). There is no single slope: it's gentle near 0 and steep further out. Lesson 05 is all about measuring the slope at one point of a curve like this.
  • Backwards reading can have two answers. f(−2) = 4 and f(2) = 4. Two buttons, same snack. That is still a function (each input has one output); it just can't be read backwards uniquely.

Neural networks need bends like this to model anything that isn't a straight line. Lesson 21 meets the most common bend in modern networks, ReLU(x) = max(0, x): 0 for every negative input, x itself otherwise, so ReLU(−2) = 0 and ReLU(3) = 3. It's two straight pieces joined at a corner, but as a whole it is not a line.

f · Worked exampleBy hand, then in Python

Evaluate. With f(x) = 2x + 6: f(4) = 14, f(6) = 18, f(8) = 22, f(10) = 26, f(12) = 30. A new 900 sq ft flat: f(9) = 2 × 9 + 6 = 24. The crossing point: f(0) = 6.

The fitted line. Lesson 03's search settled on w = 2.15, b = 5.6. Flat A: 2.15 × 4 + 5.6 = 8.6 + 5.6 = 14.2. Likewise B: 12.9 + 5.6 = 18.5, C: 17.2 + 5.6 = 22.8, D: 21.5 + 5.6 = 27.1, E: 25.8 + 5.6 = 31.4. The 900 sq ft flat: 19.35 + 5.6 = 24.95, about ₹24,950.

Slope from two points. On 2x + 6, from (4, 14) to (12, 30): (30 − 14) ÷ (12 − 4) = 16 ÷ 8 = 2.

Read backwards. Which input gives 22? 2x + 6 = 22, take 6 from both sides: 2x = 16, halve both: x = 8. That is flat C.

The curve. x² for x = −3 … 3 gives 9, 4, 1, 0, 1, 4, 9. The rises from 0 → 1 → 2 → 3 are 1, 3, 5: not constant, so not a line.

# Lesson 03's five flats: x = area in hundreds of sq ft, y = rent in thousands of rupees
X = [4, 6, 8, 10, 12]
Y = [14, 19, 22, 28, 31]

def f(x):
    """a function: one input in, one output out, nothing else touched"""
    return 2 * x + 6

print([f(x) for x in X])         # plug in each flat's size
print(f(9), f(0))                # a new 900 sq ft flat; and where the line crosses the vertical axis

def line(w, b):
    """build the straight line y = w*x + b for any pair of knobs"""
    def g(x):
        return w * x + b
    return g

fitted = line(2.15, 5.6)         # the knobs Lesson 03's search found
print([round(fitted(x), 2) for x in X])
print(round(fitted(9), 2))

print((f(12) - f(4)) / (12 - 4)) # slope = rise / run between two points
print((22 - 6) / 2)              # reading backwards: which x gives 22?

def sq(x):
    return x ** 2

print([sq(x) for x in range(-3, 4)])
print([sq(x + 1) - sq(x) for x in range(0, 3)])   # steps of 1 in x: rise is not constant

Output:

[14.2, 18.5, 22.8, 27.1, 31.4]

Notice line(w, b): it takes two knobs and hands back a function. That is exactly the "model family" idea from Lesson 03. The family is line; picking w and b picks one member of it. (The round(…, 2) is there because computers store numbers like 2.15 slightly inexactly, so 2.15 * 4 + 5.6 can print as 14.200000000000001.)

g · Common misconceptionsThree things that sound right but aren't

"f(x) means f times x."The brackets after a function's name mean "feed this in", like a function call in code. f(3) is "the output of f when the input is 3", not "f × 3". The confusion is natural, because 2(x + 1) does mean multiply: when the thing before the brackets is a number, it's multiplication; when it's a function's name, it's a call.
"A bigger b makes the line steeper."Only w changes steepness. b lifts or lowers every point by the same amount, so the line moves up or down and stays parallel to itself. If you want a line to rise faster, turn w.
"If two inputs give the same output, it's not a function."That's allowed: x² gives 4 for both −2 and 2. What a function can't do is give two outputs for the same input. Same button, same snack, every time; two buttons can still share a snack.

h · Check yourselfThree quick questions

1. For f(x) = 3x − 2, what is f(5)? Which input gives an output of 10?

Show answer

f(5) = 3 × 5 − 2 = 13. Backwards: 3x − 2 = 10, so 3x = 12, so x = 4. Check: f(4) = 12 − 2 = 10.

2. A straight line passes through (2, 7) and (6, 15). What are its slope w and its intercept b?

Show answer

Rise 15 − 7 = 8 over run 6 − 2 = 4, so w = 2. Then use one point: 7 = 2 × 2 + b, so b = 3. The line is y = 2x + 3; check the other point: 2 × 6 + 3 = 15.

3. With the fitted line ŷ = 2.15x + 5.6, flat E (x = 12) is priced at 31.4. What does the price become if b goes up by 1? If instead w goes up by 0.1?

Show answer

Raising b by 1 adds 1 to every output: 32.4. Raising w by 0.1 adds 0.1 × 12 = 1.2: 2.25 × 12 + 5.6 = 32.6. The same nudge to w would add only 0.4 for flat A (x = 4). A change to w matters more the bigger the input, which is exactly what Lesson 05's slopes will measure.

i · The one-line takeawayIf you remember one thing

A function turns each input into exactly one output, its graph is every (input, output) pair drawn as a dot, and for a line y = w·x + b, w sets the tilt and b sets where it crosses the vertical axis.
