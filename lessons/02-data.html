02 · Data: examples, features, labels, datasets

A model never sees an email, a photo or a patient. It sees a table of numbers someone chose to write down. This lesson is about that table: what goes in each row and column, and why choosing it well matters more than almost anything else.

a · Where we areZooming in on the raw material

In Lesson 01 a computer "learned" a spam rule, spam if "!" count ≥ 3, from eight emails. It got 7 of 8 right and could never do better, because email G was spam with only one "!". Today we ask why: the problem was not the learning, it was the data we gave it.

b · Why this mattersBetter data beat better algorithms

The 2012 jump in image recognition that kicked off the deep learning boom ran on ImageNet, a collection of over 14 million photos that people had labelled by hand, one by one. The network was important, but without those labels it had nothing to learn from. In real ML jobs, most of the time goes into collecting, cleaning and describing data, not into the model.

c · The intuitionA deck of flashcards

Think of how a child learns to tell a ripe mango from an unripe one. You show them mangoes, one at a time. For each one they notice a few things: colour, how soft it feels, how sweet it smells. Then you tell them the answer: "ripe" or "not ripe".

Write that on flashcards. The front of each card lists what you noticed: yellow, soft, strong smell. The back has the answer: ripe. A stack of these cards is exactly what a learning algorithm needs.

  • One card is an example.
  • Each thing written on the front is a feature.
  • The answer on the back is the label.
  • The whole stack is the dataset.

Notice what the child can and can't learn from. If you only ever wrote down colour, they could never learn that a green-skinned variety can still be ripe. What you choose to write on the front sets the limit on what can be learned.

d · How it actually worksFrom the world to a table of numbers

Example (also: sample, instance, row, data point)
One thing you have observed: one email, one house sale, one photo, one loan application.
Feature (also: attribute, input variable, column)
One measurable property of an example, written as a number: the count of "!", the floor area in square feet, the brightness of one pixel.
Label (also: target, output, y)
The answer you want the model to produce for that example: spam or not, the sale price, "cat".
Dataset
A collection of examples, usually stored as a table: one row per example, one column per feature, plus a label column.

The notation, one symbol at a time

Last lesson, x was a single number. Now each email is described by several numbers, so x becomes a list of them, called a feature vector. For our emails we will use four features:

  1. bangs: how many "!" the email contains
  2. links: how many web links it contains
  3. known: 1 if the sender is in your contacts, 0 if not
  4. words: how long the email is, in words

Email G (the one that fooled us last time) becomes the vector x = [1, 4, 0, 70]: one "!", four links, unknown sender, 70 words. Its label is y = 1 (spam).

A few more symbols you will see in every ML text:

  • n is the number of examples (rows). Here n = 8.
  • d is the number of features (columns). Here d = 4.
  • X (capital) is the whole table of features: n rows by d columns, so 8 × 4 = 32 numbers.
  • y is the list of all n labels, one per row.
  • A subscript picks a feature: x₂ is feature number 2 (links). Some books put a superscript in brackets to pick a row: x⁽⁷⁾ is the 7th example (email G).

Kinds of features, and how each becomes a number

A model can only do arithmetic, so everything must end up numeric. How you convert matters:

  • Numeric (counts, sizes, prices): use the number as is. links = 4.
  • Yes/no: use 1 and 0. known = 0.
  • Categories (city, colour, sender's email provider): don't number them 1, 2, 3. That would tell the model Chennai (3) is "more" than Delhi (1), and that Mumbai (2) sits halfway between them. Instead use one-hot encoding: one 0/1 column per category. Delhi becomes [1, 0, 0], Mumbai [0, 1, 0], Chennai [0, 0, 1].
  • Raw text, images, audio: these need a recipe to become numbers. Counting "!" is a very crude recipe for text; a photo is simply a grid of pixel brightness values. Much of this course (embeddings, tokenization) is about better recipes.

Turning raw things into useful numbers is called feature engineering. Deep learning's big selling point, which we will reach in Part 2, is that the network learns many of these recipes itself.

Kinds of labels

  • If the label is a category (spam / not spam, cat / dog / bird), the task is classification.
  • If the label is a number on a scale (price, temperature, delivery time), the task is regression.
  • If there are no labels at all and you only want to find structure (groups of similar customers), it is unsupervised learning (Lesson 18). Learning from labelled examples, like everything so far, is supervised learning.

What makes data good

  • Informative features. The features must actually carry information about the label. Email length tells you little about spam; links tell you a lot.
  • Correct labels. Labels are written by people or processes, and they contain mistakes. A model will faithfully learn those mistakes too.
  • Representative examples. The examples must look like what the model will face later. A spam filter trained only on English emails will be lost on Hindi ones.
  • No leakage. A feature must be something you would know before you know the answer. A feature like "the user moved this to the spam folder" is the label in disguise: it looks brilliant in training and is useless in real use.

Here n = 8 and d = 4. Let's score each feature on its own, the way Lesson 01 did: try every threshold, keep the one with the fewest mistakes.

  • bangs: spam if bangs ≥ 3 flags E, F, H. It misses G. 1 mistake.
  • links: spam if links ≥ 2 flags E, F, G. It misses H (only 1 link). 1 mistake.
  • known: spam if known = 0 flags C, E, F, G, H. C is a real email from someone not in your contacts. 1 mistake.
  • words: the best rule, spam if words ≤ 25, only catches F. 3 mistakes, barely better than calling everything "not spam" (4 mistakes).

Now combine the two best: spam if bangs ≥ 3 OR links ≥ 2. Walk down the table: A (0, 0) no. B (1, 1) no. C (0, 1) no. D (2, 0) no. E (3, 2) yes. F (5, 3) yes. G (1, 4) yes, thanks to links. H (4, 1) yes, thanks to bangs. All four spam caught, all four real emails left alone: 0 mistakes. The learning procedure did not get smarter; the data got richer.

The same thing in Python. The first part is plain Python; the last few lines show the numpy view, where the dataset is literally an 8 × 4 grid.

# the dataset: 8 examples (emails A..H), 4 features each
X = [  # [bangs, links, known, words]
    [0, 0, 1,  60],
    [1, 1, 1, 150],
    [0, 1, 0,  30],
    [2, 0, 1,  90],
    [3, 2, 0, 110],
    [5, 3, 0,  25],
    [1, 4, 0,  70],
    [4, 1, 0, 140],
]
y = [0, 0, 0, 0, 1, 1, 1, 1]   # 1 = spam
features = ["bangs", "links", "known", "words"]

def rule(j, t, above):
    """spam if feature j >= t (above=True) or <= t (above=False)"""
    return lambda row: int(row[j] >= t) if above else int(row[j] <= t)

def mistakes(f):
    return sum(f(row) != yi for row, yi in zip(X, y))

def best_single(j):
    options = [(mistakes(rule(j, t, a)), t, a)
               for t in sorted({row[j] for row in X}) for a in (True, False)]
    return min(options)

for j, name in enumerate(features):
    m, t, a = best_single(j)
    print(name, ">=" if a else "<=", t, "->", m, "mistakes")
# bangs >= 3 -> 1 mistakes
# links >= 2 -> 1 mistakes
# known <= 0 -> 1 mistakes
# words <= 25 -> 3 mistakes

both = lambda row: int(row[0] >= 3 or row[1] >= 2)
print(mistakes(both))          # 0

import numpy as np
Xa = np.array(X)
print(Xa.shape)                # (8, 4)   rows = examples, columns = features
print(Xa[:, 1])                # [0 1 1 0 2 3 4 1]   one feature (links) for every email
print(Xa[6])                   # [ 1  4  0 70]   one example (email G)

Two habits to take away from the code: X[:, j] reads a column (one feature across all examples) and X[i] reads a row (one example across all features). You will use both constantly. Lesson 04 explains why this grid shape, a matrix, is so central.

g · Common misconceptionsThree things that sound right but aren't

"The model looks at the email."It only ever sees the numbers your recipe produced. Our spam model has never read a single word. If the recipe drops the clue that matters, no model can recover it.
"More features is always better."A feature like words adds noise, not signal. With few examples and many weak features, a model can find patterns that are pure coincidence (Lesson 12, overfitting). Add features that plausibly carry information about the label.
"Labels are the truth."Labels are someone's judgement. People disagree, get tired and click the wrong button. Well-known benchmark datasets have been found to contain a noticeable share of wrong labels. A model is only as right as its labels.

h · Check yourselfThree quick questions

1. You want to predict a flat's rent from its area, number of bedrooms and distance to the metro. Name the example, the features and the label. Is this classification or regression?

Show answer

Each flat is one example. Area, bedrooms and metro distance are the three features (d = 3). Rent is the label. Rent is a number on a scale, so it is regression.

2. A colleague encodes the feature "city" as Delhi = 1, Mumbai = 2, Chennai = 3. What is the problem, and what should they do?

Show answer

The numbers imply an order and distances that don't exist (Chennai is not "three times" Delhi, and Mumbai is not "between" them). Use one-hot encoding: three 0/1 columns, so Delhi is [1, 0, 0], Mumbai [0, 1, 0], Chennai [0, 0, 1].

3. A spam model gets 100% accuracy in testing. One of its features is "number of times any user reported this email as spam". Should you be happy?

Show answer

No. That is label leakage: reports only exist after people have already decided it is spam. A brand-new email arriving in someone's inbox has zero reports, so in real use the feature tells the model nothing and the 100% vanishes.

i · The one-line takeawayIf you remember one thing

A dataset is a table: each row is an example, each column a feature turned into a number, and the label is the answer; a model can only learn what those columns make visible.
