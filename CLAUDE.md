# Under the Hood: working notes

Static site of interactive visualizations, live at https://cypher-ravi.github.io/under-the-hood/.
Every push to `main` redeploys through `.github/workflows/pages.yml` (about 1 minute).

## Rules
- Commit as the user only: `git -c user.name="cypher-ravi" -c user.email="ravikdev1999@gmail.com" commit ...`.
  **No Claude co-author trailer or any Claude attribution** in commits, PRs or pages.
- No build step, no dependencies. Plain HTML/CSS/JS, one file per page. Fonts from Google Fonts only.
- Colors only through tokens in `shared/lab.css` (light and dark). Every page must fit a 400px-wide screen with no sideways scroll.
- After changing `shared/lab.css`, bump the `?v=N` query on every page's stylesheet link (currently `v=8`).
- Write explanations and problem statements in our own words. Credit Hello Interview (design questions) and Codeintuition (DSA pattern structure) as inspiration; never copy their text.
- Verify facts (dates, names, numbers) with a quick search before putting them in a "story" section.
- Check each new page once with Playwright (desktop + 400px width, look for console errors), then push.

## Structure
- `index.html`: gallery with four tabs (Concepts, Design questions, DSA patterns, AI lessons), rendered from `topics/registry.js`. `#questions`, `#dsa` and `#lessons` deep-link to a tab.
- `topics/registry.js`: `TOPICS`, `QUESTIONS`, `DSA`, `LESSONS` (array of `{ part, lessons: [{ num, slug, title, status, blurb }] }`). Flip an entry's `status` to `"ready"` when its page ships.
- `topics/<slug>.html`: concept pages. Sections: simulation, worked example, story (history), first principles (`.qa` rows), what to notice, interview angle.
- `topics/registry.js` `QUESTIONS` entries carry `level: "hld" | "lld"`; the Design questions tab shows two groups, "High-level design" and "Low-level design", and the qnav switcher groups them the same way.
- `questions/<slug>.html`: design questions (high-level). Sidebar via `<aside class="qnav" id="qnav" data-current="slug">` + `shared/qnav.js`. Sections carry `data-nav`, `data-num`, `data-time`. Steps follow Hello Interview's framework: requirements, core entities, API, high-level design (staged animated diagram), deep dives; then worked example, first principles, story, follow-ups, concept links.
- `questions/lld-<slug>.html`: low-level design pages, same chrome as design questions (qnav sidebar, sections with `data-nav`/`data-num`/`data-time`, about 45 min). Sections: requirements (functional + non-functional), core entities and responsibilities, class diagram (inline SVG, UML inheritance/composition/association with multiplicities), interfaces of the main classes, design patterns used and why (only where they fit), interactive walkthrough (a simulation or `Stepper` running the same logic as the code), code (short runnable Python, run before shipping, exact output shown), deep dives (concurrency, extensibility, SOLID trade-offs), worked example, follow-ups, related concept and HLD links (link LLD and HLD versions of a problem both ways). Registry entries add `patterns: [...]`. `questions/lld-parking-lot.html` is the reference example.
- `dsa/<slug>.html`: DSA pattern pages. Same sidebar with `data-kind="dsa"`. Sections: the idea, how to spot it, template, problems (question box with example I/O + hint, then a `Stepper`), why it works.
- `lessons/<NN>-<slug>.html`: AI lessons, one concept each, title "AI Lesson NN · <topic>". Reading column (`.lesson-wrap`) with a back link to `../index.html#lessons`. Sections a–k: where we are, why this matters, the intuition, how it actually works, see it (inline SVG, plus a widget computing real values), worked example (by hand, then a Python snippet whose output matches the page), common misconceptions, check yourself (3 `<details>` questions; put the question inside the summary as `<summary><span class="q">…</span><span class="sa">Show answer</span></summary>` so it shows while closed), one-line takeaway, next time, go deeper. A `.pn` nav at the bottom links the previous and next lessons (planned ones as unlinked text); update the previous lesson's "next" link when a lesson ships. `lessons/01-what-ai-is.html` is the reference example.
- Math toolkit: `lessons/m<NN>-<slug>.html`, title "Math MNN · <topic>", registered in `window.MATH` (`{ num, slug, title, status, blurb, usedBy: [lesson nums] }`) and shown as a "Math toolkit" group at the top of the AI lessons tab (no new tab). LESSONS entries carry the reverse `math: [nums]`. Same chrome and sections as AI lessons, except (a) is "Where this is used" (links to the AI lessons) and (j) is "Back to the course". Assume rusty school math: define every symbol, small numbers before formulas, show why each rule is true. Visual-first: every numbered step in "how it actually works" gets its own inline SVG figure right under its text, paired with a worked example in real numbers (caption states the example), drawn so the picture shows why the rule holds; steps about something that changes get a small interactive (slider or Step/Reset) computing real values (at least 2 per page besides the main labs); the misconceptions section shows at least one wrong-vs-right picture. Figures use ~360-wide viewBoxes so labels stay ≥12px on a phone, and must read in light and dark. Each AI lesson that needs math opens with a `<aside class="mathneed">` "Math you'll need" box (style block in the lesson's own `<style>`, see `lessons/03-model-is-a-function.html`) linking its `math` entries; planned ones as plain text. `lessons/m01-functions-graphs.html` is the reference example.
- Course mode and progress: every page (and `index.html`) loads `shared/progress.js` as its last script. It shows a page one bite-sized step at a time (Hello Interview style): a step bar with "Step N of M", an "All steps" list with checkmarks and minutes, and per-step "Covered" checkbox, Back and "Mark covered & next". Readers can switch to "show every step on one page". Steps are the `<section>` children of `<main>`: `data-step="Title"` names a step, `data-step-join` merges a section into the previous step, `data-split` turns each `<h3>` inside a section into its own step; without these, a section with an id starts a step and one without an id joins the previous step. Lessons and math pages use: a `data-step="Start here"` (b, c join; the "Math you'll need" box sits at the top of section a), d `data-step="How it works" data-split`, e "See it", f "Worked example", g "Check your understanding" (h joins), i "Wrap-up" (j, k join). Keep each step digestible (roughly 150–400 words plus its figure or widget); split long sections rather than writing walls of text. Checkmarks live in `localStorage` (`uth-progress-v1`); the gallery shows a covered button on every card, a per-tab "N of M covered" bar, and copy/paste/reset progress tools in the footer. Widgets must redraw on `resize` (fired when a step is shown), since steps start hidden.
- `shared/stepper.js`: `Stepper(root, { code, inputs, presets, build(values) -> {frames}|{error}, draw(frame) })`, plus `drawArray(values, {ptr, mark})` and `parseNums(text)`. `dsa/two-pointers.html` is the reference example.
