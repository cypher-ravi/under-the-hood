Simultaneous Traversal

Walk two sequences at the same time, one pointer in each. At every step you compare the two current elements, act on one (or both), and advance only the pointer you used. Two sorted arrays can be merged, intersected or matched in a single pass, without nested loops and without sorting again.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

The smallest remaining element is always at a front

Take two sorted piles of cards. The smallest card left anywhere must be on top of one of the two piles, because each pile is sorted. So you only ever need to compare two cards, the two tops, to know what comes next. Take that card, and the pile it came from shows a new top.

Each comparison uses up at least one element, so the whole walk takes at most n + m steps. The alternatives are slower. Comparing every element of one array with every element of the other takes n × m steps. Gluing the arrays together and sorting again takes (n + m) log(n + m) and throws away the order you already had.

Recognizing the pattern

Signals in the problem statement

  • There are two inputs (arrays, strings or lists), and both are sorted or ordered.
  • The task is to combine them (merge), compare them (common elements, differences) or check that one follows the other (subsequence).
  • The expected complexity is O(n + m), or the statement says the inputs are already sorted, which is a hint not to sort again.
  • You must write into one of the inputs in place, and it has spare room at the end.

Compared with Two Pointers: there, both pointers live in the same array and usually move toward each other. Here each pointer owns its own sequence, and both usually move forward.

Template

The skeleton you adapt

i, j = 0, 0
while i < len(A) and j < len(B):
    # look at A[i] and B[j]
    if they match:
        use both; i += 1; j += 1
    elif A[i] < B[j]:
        use or skip A[i]; i += 1
    else:
        use or skip B[j]; j += 1
# one side ran out: handle what's left of the other

Problems differ only in what "use" means and in what to do with the leftovers once one side runs out. Forgetting the leftovers is the most common bug with this pattern.

Problem 1 · Merge

Merge two sorted arrays

Question

Given two arrays, each sorted in increasing order, return a single array with every element from both, also sorted.

InputA = [1, 4, 7, 9], B = [2, 3, 8]
Output[1, 2, 3, 4, 7, 8, 9]
Think first: which element goes out next?

The next output is the smaller of the two fronts, A[i] or B[j]. Take it and advance only that pointer. When one array runs out, the rest of the other is already sorted and larger than everything written, so copy it straight across.

Time O(n + m)Space O(n + m) for the outputConcatenate and sort: O((n + m) log(n + m))
Problem 2 · Match

Is it a subsequence?

Question

Given a short string s and a longer string t, return true if you can delete some characters of t (possibly none), without reordering the rest, and get s.

Inputs = "ace", t = "abcde"
Outputtrue (a, c, e appear in order)
Think first: is it ever wrong to match early?

No. If s[i] equals t[j], matching it now leaves the most of t for the rest of s. So scan t once, and advance i only on a match. If i reaches the end of s, you're done.

Time O(len t)Space O(1)
Problem 3 · Intersect

Common elements of two sorted arrays

Question

Given two sorted arrays, return the elements they share. If a value appears twice in both, include it twice.

InputA = [1, 2, 2, 4, 6, 8], B = [2, 2, 3, 6, 9]
Output[2, 2, 6]
Think first: the fronts differ. Which one can go?

If A[i] is smaller than B[j], then A[i] is smaller than everything left in B too, because B is sorted. It can't match anything, so skip it. Equal fronts are a match: record it and advance both.

Time O(n + m)Space O(1) besides the outputNested loops: O(n × m)
Problem 4 · Backwards

Merge into the first array, in place

Question

Array A holds m sorted values followed by n empty slots. Array B holds n sorted values. Merge B into A so that A ends up fully sorted, without using another array.

InputA = [1, 4, 7, _, _, _], B = [2, 5, 6]
OutputA = [1, 2, 4, 5, 6, 7]
Think first: why does merging from the front go wrong?

Writing at the front of A would overwrite values of A you haven't placed yet. The empty space is at the end, so fill it from the end: compare the two largest remaining values and put the larger one in the last free slot. The write pointer can never overtake the read pointer in A.

Time O(n + m)Space O(1)
Correctness

Why a single pass is enough

Invariant

Everything before i in A and before j in B has already been handled correctly, and nothing after them has.

Each step

Because both arrays are sorted, the front that is smaller can't pair with anything later in the other array. Handling it now keeps the invariant true.

Termination

Every step advances at least one pointer, so the loop runs at most n + m times.

History

This merge step is the heart of merge sort, which is usually credited to John von Neumann in 1945. External sorting on tape drives relied on it for decades, because tapes can only be read in order.
