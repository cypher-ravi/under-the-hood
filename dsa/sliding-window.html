Sliding Window

Keep a contiguous range of the array and a small summary of what is inside it. Move the right edge to take one element in and the left edge to let one go, updating the summary as you go. Nothing gets recomputed from scratch, so every subarray you care about is checked in one pass.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

Neighbouring subarrays share almost everything

Take the subarray from index 2 to 5 and the one from 3 to 6. They share indices 3, 4 and 5. If you already know the sum of the first, the sum of the second is that sum, plus the element that came in on the right, minus the one that left on the left. That is two operations, not four.

A brute-force scan recomputes every range from scratch, which costs O(n·k) for windows of size k, or O(n²) when the size can vary. A sliding window keeps a running summary (a sum, a letter count, a set) and patches it by one element at each move. Each index enters the window once and leaves at most once, so the whole scan is O(n).

Three ways the pattern shows up

Fixed size

The window length k is given. Every step adds one on the right and drops one on the left, so the size never changes.

Variable, longest

Grow the right edge as long as the window stays valid. When it breaks, shrink from the left until it is valid again, then record the size.

Variable, shortest

Grow until the window first becomes valid, then shrink from the left for as long as it stays valid, recording each size on the way.

Recognizing the pattern

Signals in the problem statement

  • The question is about a contiguous piece of the input: a subarray, a substring, a run of days.
  • It asks for the longest, shortest, maximum, minimum or count of such pieces.
  • A window size k is given outright (fixed window), or there is a condition like "at most two distinct", "no repeats" or "sum at least T" (variable window).
  • The condition is monotone: if a window breaks it, every larger window containing it breaks it too. That is what makes shrinking from the left safe.

Counter-signals: if the elements don't have to be next to each other (a subsequence), you are probably looking at DP. If a sum condition allows negative numbers, growing the window can make the sum smaller, so monotonicity fails; prefix sums with a hash map are the usual fix.

Template

The two skeletons you adapt

Fixed size k

state = summary(a[0:k])
record(state)
for R in range(k, len(a)):
    add(a[R])          # comes in on the right
    remove(a[R - k])   # leaves on the left
    record(state)

Variable size

L = 0
for R in range(len(a)):
    add(a[R])
    while window_is_bad():   # or: while still good
        remove(a[L])
        L += 1
    record(R - L + 1)

What changes between problems is the state you keep (a sum, a count per letter, a set) and the condition that tells you when to shrink. In an interview, name both before writing code. For "longest" problems you record after shrinking; for "shortest" problems you record inside the shrink loop, while the window is still valid.

Problem 1 · Fixed size

Largest sum of k consecutive numbers

Question

Given an array of integers and a number k, return the largest sum you can get by adding up k elements that sit next to each other.

Input[2, 1, 5, 1, 3, 2], k = 3
Output9 (5 + 1 + 3)
Think first: how does one window's sum become the next?

Moving the window one step right brings in a[R] and pushes out a[R − k]. Everything in between stays. So the new sum is the old sum plus one number minus another, no loop over the window needed.

Time O(n)Space O(1)Re-adding every window: O(n·k)
Problem 2 · Fixed size

Every place an anagram starts

Question

Given a text and a shorter pattern, both in lowercase letters, return every index in the text where a rearrangement of the pattern begins.

Inputtext "cbaebabacd", pattern "abc"
Output[0, 6] ("cba" and "bac")
Think first: what makes two strings anagrams?

They have the same count of each letter. The window must be exactly as long as the pattern, so it is a fixed window. Keep a letter count for the window, add the new right letter, remove the old left letter, and compare with the pattern's counts. Comparing 26 counters is constant work; to go further, track how many letters currently match and update that number instead.

Time O(n) with a 26-letter alphabetSpace O(1)Sorting every window: O(n·m log m)
Problem 3 · Variable, longest

Longest substring with no repeated character

Question

Given a string, return the length of the longest stretch of consecutive characters in which no character appears twice.

Input"abcabcbb"
Output3 ("abc")
Think first: when the window breaks, where can it restart?

Keep the window's characters in a set. When the new character s[R] is already inside, no window that still contains the earlier copy can be valid, so drop characters from the left until that copy is gone. Then add s[R] and record the size. A map from character to last index lets L jump there in one move instead of stepping.

Time O(n)Space O(alphabet)Checking every substring: O(n²) or worse
Problem 4 · Variable, shortest

Shortest subarray whose sum reaches a target

Question

Given an array of positive integers and a target, return the length of the shortest run of consecutive elements whose sum is at least the target. Return 0 if no run gets there.

Input[2, 3, 1, 2, 4, 3], target 7
Output2 ([4, 3])
Think first: once the sum is big enough, what should you try?

Grow R until the sum reaches the target. That window is valid, so record its length, then see whether it still works with the leftmost element removed. Keep shrinking while it stays valid. Because every number is positive, removing an element always lowers the sum, so once it drops below the target there is no point shrinking further.

Time O(n)Space O(1)Trying every start: O(n²)
Correctness

Why the left edge never needs to go back

Monotone rule

The condition must behave well under growth: if [L, R] is invalid, then every window that contains it is invalid too. Repeats stay repeats, and with positive numbers a sum only grows.

Invariant

After each step, L is the smallest start for which [L, R] is valid. Any start before L was ruled out for some earlier R, and by the rule above it stays ruled out for every larger R. So L only ever moves right.

Cost

R moves n times. L moves at most n times in total, even though a single step can move it several places. The inner while loop looks like O(n²) but adds up to O(n) over the whole run.

In an interview

State the window state, the shrink condition and why it is monotone. Then point out the amortized argument: each element enters once and leaves once.
