Sliding Window

Look at a run of neighbouring elements through a window, then slide it along. One element comes in on the right, one leaves on the left, and you patch a running total instead of starting over.

In 30 seconds
  • What: a range from L to R plus a small summary of what's inside it: a sum, letter counts, or a set.
  • When: the question is about a contiguous piece (subarray, substring) and asks for the longest, shortest or best one.
  • Why it's fast: each element enters the window once and leaves at most once. O(n) instead of O(n·k) or O(n²).
  • The one thing to get right: when to shrink from the left, and why a window you dropped can never become useful again.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, by example

Best sum of 4 numbers in a row

Here are seven numbers: 4, 2, 7, 1, 5, 3, 6. Which four neighbours have the biggest sum?

The slow way adds up each group of four from scratch. But look at two groups side by side. Moving one step right only changes two numbers: one comes in, one goes out. Everything in the middle stays.

WindowInOutSum
0–3––4 + 2 + 7 + 1 = 14
1–45414 + 5 − 4 = 15
2–53215 + 3 − 2 = 16 (best)
3–66716 + 6 − 7 = 15

After the first window, each slide costs two operations no matter how wide the window is. With a million numbers and windows of 1,000, that's about 2 million operations instead of about a billion.

Neighbouring windows share almost everything. Keep a running summary and patch it with what came in and what went out, instead of recomputing.

The idea, continued

Three ways the pattern shows up

The window either has a fixed size, or it stretches and shrinks. Which one you're in decides how the left edge moves.

Fixed size

The length k is given. Each step adds one on the right and drops one on the left, so the size never changes.

Recognizing the pattern

Signals in the problem statement

Reach for a sliding window when you see one or more of these:

  • The question is about a contiguous piece: a subarray, a substring, a run of days.
  • It asks for the longest, shortest, largest or count of such pieces.
  • A size k is given (fixed window), or there's a rule like "no repeats", "at most two kinds" or "sum at least T" (stretchy window).
  • Breaking the rule is permanent under growth: if a window breaks it, every bigger window around it breaks it too. That's what makes shrinking from the left safe.

When not to: if the elements don't have to sit next to each other (a subsequence), think dynamic programming instead. And if a sum rule allows negative numbers, adding an element can make the sum smaller, so the "permanent" property fails. Prefix sums with a hash map are the usual fix there.

Template

The two skeletons you adapt

Fixed size k

state = summary(a[0:k])
record(state)
for R in range(k, len(a)):
    add(a[R])        # in on the right
    remove(a[R - k]) # out on the left
    record(state)

Stretchy

L = 0
for R in range(len(a)):
    add(a[R])
    while window_is_bad():
        remove(a[L])
        L += 1
    record(R - L + 1)

To adapt it to a new problem, answer three questions:

  1. Fixed or stretchy? If the problem gives you k, it's fixed. If it gives you a rule, it's stretchy.
  2. What summary do you keep? A sum, a count per letter, or a set of what's inside. It must be cheap to add one element and remove one.
  3. When do you shrink, and where do you record? For "longest", shrink while the window is bad and record after. For "shortest", shrink while it's still good and record inside the loop.
Problem 1 · Fixed size

Largest sum of k consecutive numbers

Question

Given an array of integers and a number k, return the largest sum you can get by adding up k elements that sit next to each other.

Input[2, 1, 5, 1, 3, 2], k = 3
Output9 (5 + 1 + 3)

When the window slides one step, which numbers actually change?

The obvious way

For every starting point, add up the next k numbers. There are about n starts and each costs k additions, so O(n·k).

Key insight

Sliding right brings in a[R] and pushes out a[R − k]. Everything in between stays. So the new sum is the old sum plus one number minus another.

The plan

  1. Add up the first k numbers. That's the best so far.
  2. For each R from k to the end: add a[R], subtract a[R − k].
  3. If the new sum beats the best, keep it.
  4. Return the best.

Starting the best at 0. If every number is negative the answer is below zero. Start from the first window's sum instead.

Problem 2 · Fixed size

Every place an anagram starts

Question

Given a text and a shorter pattern, both in lowercase letters, return every index in the text where a rearrangement of the pattern begins.

Inputtext "cbaebabacd", pattern "abc"
Output[0, 6] ("cba" and "bac")

Two words are anagrams. What do they have in common, letter by letter?

The obvious way

At every start, take the next m letters (m is the pattern length), sort them and compare with the sorted pattern. That's O(n·m log m).

Key insight

Anagrams have the same count of each letter. The window is always exactly m letters long, so it's a fixed window: slide it and change just two counts per step, one up and one down.

The plan

  1. Count the pattern's letters.
  2. For each R: add one to the count of text[R].
  3. Once the window is longer than m, subtract one for the letter at R − m.
  4. If the counts match the pattern's, record the start R − m + 1. With 26 letters this check is constant work.

Watch it run

The top row is the text with the window over it. The boxes below show each letter's count in the window next to what the pattern needs. A box turns green when they agree; all green means an anagram.

Time O(n) with a 26-letter alphabetSpace O(1)Sorting every window: O(n·m log m)

Forgetting to remove the letter that leaves on the left. The counts keep growing and never match the pattern again.

Problem 3 · Stretchy, longest

Longest substring with no repeated character

Question

Given a string, return the length of the longest stretch of consecutive characters in which no character appears twice.

Input"abcabcbb"
Output3 ("abc")

A repeat just showed up. Where is the earliest the next good window can start?

The obvious way

Try every substring and check it for repeats. There are about n²/2 substrings, so this is O(n²) at best.

Key insight

If the new character s[R] is already in the window, every window that still holds the earlier copy is broken. So drop characters from the left until that copy is gone. L never needs to move back.

The plan

  1. Keep a set of the window's characters. L starts at 0.
  2. For each R: while s[R] is in the set, remove s[L] and move L right.
  3. Add s[R] and record the length R − L + 1 if it's the best.
  4. Speed-up: store each character's last index, so L can jump past the copy in one move.

Watch it run

Blue band: the current window. Amber borders: the new character and its earlier copy. Red border: dropped from the left. Green dashed outline: the best window so far. The chips below are the set.

Time O(n)Space O(alphabet)Checking every substring: O(n²) or worse

With the last-index speed-up, moving L backwards to an old copy that's already outside the window. Use L = max(L, last[c] + 1).

Problem 4 · Stretchy, shortest

Shortest subarray whose sum reaches a target

Question

Given an array of positive integers and a target, return the length of the shortest run of consecutive elements whose sum is at least the target. Return 0 if no run gets there.

Input[2, 3, 1, 2, 4, 3], target 7
Output2 ([4, 3])

The sum just reached the target. What's the next thing worth trying?

The obvious way

For every start, keep adding numbers until the sum reaches the target. O(n²).

Key insight

Once the window reaches the target, record its length and try dropping the leftmost number. Every number is positive, so dropping one always lowers the sum. Keep shrinking while it still reaches the target; once it falls short, grow on the right again.

The plan

  1. L = 0, sum = 0, best = infinity.
  2. For each R: add a[R] to the sum.
  3. While sum ≥ target: record R − L + 1, subtract a[L], move L right.
  4. Return best, or 0 if it never changed.

Watch it run

Blue band: the current window. Green border: just came in. Red border: just dropped from the left. Green dashed outline: the shortest window so far.

Time O(n)Space O(1)Trying every start: O(n²)

Shrinking with if instead of while. Dropping only one element per step can miss a much shorter window.

Correctness

Why the left edge never goes back

The whole argument fits in three sentences:

Always true

L is the earliest start that can still give a good window ending at R. Every start before L has already been shown to fail.

Each step

When a window breaks the rule, every bigger window around it breaks it too: a repeat stays a repeat, and a sum of positives only grows. So a start that failed once fails for every later R, and L only moves right.

It ends

R moves n times and L moves at most n times in total. The inner while looks like O(n²), but over the whole run it adds up to O(n).

In an interview: name the summary you keep and the shrink rule, then say why the rule stays broken as the window grows. Finish with "each element enters once and leaves once", which is the O(n) argument.

Cheat sheet

Best sum of k

Sum += new − old. Track the best.

Anagrams

Fixed window of letter counts. Match the pattern's counts.

No repeats

Repeat inside? Drop from the left until it's gone.

Shortest to target

While sum ≥ target: record, drop the left.
