Monotonic Stack

Walk the array once and keep a stack of elements still waiting for their answer, like "the next bigger value". When a new value arrives, it answers everyone on top it beats, and they leave for good.

In 30 seconds
  • What: a stack of indices whose values stay sorted from bottom to top ("monotonic" means always going one way).
  • When: for every element you need the nearest bigger or smaller element to its left or right.
  • Why it's fast: each index is pushed once and popped at most once, so the whole run is at most 2n stack operations. O(n) instead of O(n²).
  • The one thing to get right: what a pop means (who gets an answer) and whether ties pop (< or <=).

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, by example

Find the next bigger number for each one

Take [2, 7, 3, 5, 4, 6, 8]. For each number we want the first bigger number to its right. The obvious way scans right from every position. On a falling list like 9, 8, 7, …, 1 every scan runs to the end: about n²/2 looks.

Flip it around. Walk left to right and keep a stack of numbers still waiting for their answer. When a new number arrives, it is the answer for every waiting number it beats.

777 beats 2: 2's answer is 7. Pop it. 7 waits.

Because the waiting numbers are sorted, a new number only needs to check the top of the stack. Every pop hands out one answer, and no number is ever looked at again after it leaves.

The idea, continued

Three ways the pattern shows up

The loop is always the same. What changes is who gets an answer at the moment of a pop.

Answer the popped

The arriving element is the "next greater" for every index it pops. Whatever is left at the end has no answer.

Recognizing the pattern

Signals in the problem statement

Reach for a monotonic stack when you see one or more of these:

  • For every element, you need the nearest element to the left or right that is bigger (or smaller).
  • Phrases like "next warmer day", "how many days until", "how far back", "span", "visible", "blocked by".
  • For each element, you need the widest range in which it is the smallest (or largest), as with histogram rectangles.
  • The brute force is "for each i, scan outward until something stops you", which is O(n²) on sorted or reversed input.

When not to: for the maximum of a sliding window, elements also leave from the front as the window moves, so you need a monotonic deque (a queue open at both ends). And for "the k-th largest overall" rather than "the nearest bigger", use a heap.

Template

The skeleton you adapt

stack = []   # indices still waiting
for i, x in enumerate(a):
    while stack and a[stack[-1]] < x:
        j = stack.pop()
        # x is j's next greater
    # stack[-1] is i's prev greater
    stack.append(i)
# leftovers never got an answer

To adapt it to a new problem, answer three questions:

  1. Bigger or smaller? To find greater values, pop smaller ones (the stack falls bottom to top). To find smaller values, flip the comparison (the stack rises).
  2. Who gets the answer? The popped index ("next" questions), the arriving index ("previous" questions), or both (ranges).
  3. Do ties pop? < or <= decides what happens with equal values. Most bugs hide here. And store indices, not values: an index gives you both the value and the distance.
Problem 1 · Answer the popped

Next greater element to the right

Question

Given an array of integers, build an array of the same length where position i holds the first value to the right of i that is strictly larger than a[i], or −1 if there isn't one.

Input[4, 2, 6, 3, 1, 5, 7]
Output[6, 6, 7, 5, 5, 7, -1]

When 6 arrives, which earlier numbers are still waiting for something bigger?

The obvious way

For each index, scan right until you find a bigger value. On a falling array every scan runs to the end, so it's O(n²).

Key insight

Before 6 arrives, 4 and 2 are both waiting, and 6 is the first bigger value for both. Keep waiting indices on a stack. The newest waiter is always the smallest, so it's the first one a new value can answer. Once answered, an index is never needed again.

The plan

  1. Fill res with −1. Start with an empty stack.
  2. For each x: while the top's value is smaller than x, pop index j and set res[j] = x.
  3. Push the current index. It waits for something bigger.
  4. Indices left at the end keep −1.

Watch it run

Top row is the array: blue is the current element, amber outline means waiting on the stack, green was just answered, grey was answered earlier. The bottom row fills in as answers arrive.

Time O(n)Space O(n) for the stackScan right from each index: O(n²)

Pushing values instead of indices. You learn that a value got its answer, but not which position in res to write it to.

Problem 2 · Answer the popped

How many days until a warmer day?

Question

You get a list of daily temperatures. For each day, report how many days you'd wait until a strictly warmer day. If no warmer day ever comes, report 0.

Input[71, 69, 68, 72, 70, 74, 73]
Output[3, 2, 1, 2, 1, 0, 0]

This is Problem 1 with a different answer. What do you need to know about a waiting day to compute it?

The obvious way

From each day, scan ahead until a warmer day appears. A long cold spell makes every scan long: O(n²).

Key insight

It's next greater element, but the answer is a distance. When warmer day i pops waiting day j, day j waited i − j days. That's why the stack holds indices: a temperature alone can't tell you how long ago it was.

The plan

  1. Fill wait with 0. Start with an empty stack of days.
  2. For each day i: while the top day is colder, pop j and set wait[j] = i − j.
  3. Push day i.
  4. Days left on the stack keep 0.

Watch it run

The result row fills in out of order: a day gets its answer when a warmer day pops it, not when you walk past it.

Time O(n)Space O(n)Scan ahead from each day: O(n²)

Popping on equal temperatures (<=). A day just as warm isn't warmer, so for 65, 65, 66 the first day must wait 2, not 1.

Problem 3 · Answer the arriving

Stock price span

Question

You get a stock's closing price for each day. The span of a day is the number of consecutive days, ending with that day and counting backwards, on which the price was less than or equal to that day's price. Return the span of every day.

Input[100, 80, 60, 70, 60, 75, 85]
Output[1, 1, 1, 2, 1, 4, 6]
Why day 575 ≥ 60, 70, 60 before it; 80 stops the run, so span = 4

Today's price is 75. Can an earlier day priced 70 ever stop a later day's run?

The obvious way

From each day, walk back while the price is no higher. On a rising price list every walk goes all the way back: O(n²).

Key insight

A run stops at the nearest earlier day with a strictly higher price. Once today is at least as high as an earlier day, that earlier day can never stop anyone later: today is closer and just as tall. So pop it for good. After popping, the top of the stack is the day that stops today's run.

The plan

  1. Start with an empty stack of days.
  2. For each day i: pop while the top day's price is ≤ today's.
  3. left = the top day, or −1 if the stack is empty. Span = i − left.
  4. Push day i.

Watch it run

Here the answer goes to the arriving day, worked out from whatever is left on top after the pops. The line under the picture names the day that stopped the run.

Time O(n)Space O(n)Walk back from each day: O(n²)

Forgetting the empty stack. If no earlier day was higher, the span is i + 1 (left = −1), not 1.

Problem 4 · Both sides at once

Largest rectangle in a histogram

Question

A histogram has bars of width 1 with the given heights, standing side by side. Find the area of the largest rectangle that fits entirely inside the bars.

Input[2, 1, 5, 6, 2, 3]
Output10 (height 5 across the bars 5 and 6)

If bar j is the shortest bar in the rectangle, how far left and right can the rectangle stretch?

The obvious way

For each bar, spread left and right while the bars are at least as tall, then compute height × width. O(n²).

Key insight

The best rectangle has some shortest bar j, and it stretches from the nearest shorter bar on the left to the nearest shorter bar on the right. Keep a stack whose heights rise. When a shorter bar arrives at i, it's the right wall for each bar it pops, and the new top is the left wall. Width = i − left − 1.

The plan

  1. Pretend there's an extra bar of height 0 at the end.
  2. For each bar i: while the top bar is at least as tall, pop j.
  3. left = the new top, or −1. Area = h[j] × (i − left − 1). Keep the best.
  4. Push bar i. Return the best.

Watch it run

Amber bars are on the stack (heights rise from bottom to top). The red bar is being popped and the blue box is the rectangle it measures. The green dashed outline is the best so far.

Time O(n)Space O(n)Spread out from every bar: O(n²)

Leaving out the height-0 bar at the end. Bars still on the stack never get measured, so a rising histogram like 1, 2, 3, 4, 5 returns 0 instead of 9.

Correctness

Why one pass is enough

Here is the argument for next greater element (Problem 1). The others follow the same shape.

Always true

The stack holds exactly the indices seen so far that haven't met a bigger value, and their values never rise from bottom to top.

Each step

When x pops index j, nothing between j and x was bigger than a[j]: anything bigger would have popped j already. So x is the first bigger value, not just a bigger one. Pushing x after the pops keeps the stack falling.

It's linear

The inner loop can pop many times for one x, which looks quadratic. But each index is pushed once and popped at most once, so the whole run has at most n pushes and n pops: 2n operations. The steppers count them for you.

In an interview: name the stack's order ("values fall from bottom to top"), say what a pop means ("the arriving value answers the popped one"), and give the push-once, pop-once argument for O(n). Then say how you handle ties.

Recap

Cheat sheet

Next greater

Pop smaller tops; the arriving value answers them.

Days until warmer

Same loop; the answer is i − j, so store indices.

Stock span

Pop tops ≤ today; span = i − top (or i + 1).

Largest rectangle

Rising stack; a pop's width is i − left − 1. Add a 0 bar.
