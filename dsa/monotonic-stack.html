Monotonic Stack

Walk the array once and keep a stack of indices whose values stay in sorted order from bottom to top. When a new value would break that order, pop until it doesn't. Every pop is a moment where one element meets its answer: the next bigger value, the previous bigger value, or the edge of a rectangle. Each index goes on once and comes off at most once, so the whole thing is O(n).

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

A waiting line that only keeps useful candidates

Take the question "for each element, what is the first bigger element to its right?" The direct approach scans right from every position until it finds something bigger. On a falling array like 9, 8, 7, …, 1 each scan runs to the end, which is n(n−1)/2 comparisons.

Flip it around. Scan left to right and keep the elements that are still waiting for their answer. Notice that the waiting elements are always in decreasing order: if a bigger value arrived after a smaller one, it would already have answered it. So the waiting list is a stack whose values fall from bottom to top. When a new value x arrives, everything on top that is smaller than x gets its answer (x) and leaves. Then x joins the stack and waits too. The stack's order is the "monotonic" part; the pops are where the work happens.

Three ways the pattern shows up

Answer the popped

The arriving element is the "next greater" for every index it pops. Whatever is left on the stack at the end has no answer.

Answer the arriving

After popping, whatever sits on top is the nearest earlier element that survived: the "previous greater" for the new index.

Both sides at once

When an index is popped, the arriving element is its right boundary and the new top is its left boundary. That gives the widest range it controls.

Recognizing the pattern

Signals in the problem statement

  • For every element, you need the nearest element to the left or right that is bigger (or smaller).
  • Phrases like "next warmer day", "how many days until", "how far back", "span", "visible", "blocked by".
  • You need, for each element, the widest range in which it is the minimum (or maximum): histogram rectangles, sums of subarray minimums.
  • The brute force is "for each i, scan outward until a condition fails", which is O(n²) on sorted or reversed input.

Counter-signal: if you need the maximum of a sliding window of fixed size, elements also leave from the front when they fall out of the window. That's a monotonic deque, a close cousin. And if the question is about the k-th largest overall, not the nearest, reach for a heap.

Template

The skeleton you adapt

stack = []                         # indices; their values stay sorted
for i, x in enumerate(a):
    while stack and breaks_order(a[stack[-1]], x):
        j = stack.pop()
        # x is the next greater/smaller element for j
    # stack[-1], if any, is the previous greater/smaller for i
    stack.append(i)
# indices still on the stack never found an answer

Two choices make each problem. Which order the stack keeps: pop smaller values to find greater ones (a decreasing stack), or pop larger values to find smaller ones (an increasing stack). And strict or not: < versus <= decides what happens with equal values, which is where most bugs hide. Store indices, not values: you can always look the value up, but you can't recover a distance from a value.

Problem 1 · Answer the popped

Next greater element to the right

Question

Given an array of integers, build an array of the same length where position i holds the first value to the right of i that is strictly larger than a[i], or −1 if there isn't one.

Input[4, 2, 6, 3, 1, 5, 7]
Output[6, 6, 7, 5, 5, 7, -1]
Think first: who is still waiting when 6 arrives?

Before 6 arrives, 4 and 2 haven't seen anything bigger. 6 is the first bigger value for both, so it answers them at once. After that they're done and never need to be looked at again. Keep the unanswered indices on a stack; the newest one is always the smallest, so it's the first one a new value can answer.

Array: blue = current element, amber outline = waiting on the stack, green = just answered, grey = answered earlier.

Problem 2 · Answer the popped

How many days until a warmer day?

Question

You get a list of daily temperatures. For each day, report how many days you'd wait until a strictly warmer day. If no warmer day ever comes, report 0.

Input[71, 69, 68, 72, 70, 74, 73]
Output[3, 2, 1, 2, 1, 0, 0]
Think first: what do you need to remember about a waiting day?

This is Problem 1 asking for a distance instead of a value. The answer for day j is i − j, where i is the warmer day that pops it. That's why the stack stores indices: a temperature alone can't tell you how long ago it was.

The result row fills in out of order: a day gets its answer when a warmer day pops it, not when you pass it.

Time O(n)Space O(n)Scan ahead from each day: O(n²)
Problem 3 · Answer the arriving

Stock price span

Question

You get a stock's closing price for each day. The span of a day is the number of consecutive days, ending with that day and counting backwards, on which the price was less than or equal to that day's price. Return the span of every day.

Input[100, 80, 60, 70, 60, 75, 85]
Output[1, 1, 1, 2, 1, 4, 6]
Why day 575 ≥ 60, 70, 60 before it; 80 stops the run, so span = 4
Think first: which earlier days can ever stop a later run?

The span stops at the nearest earlier day with a strictly higher price. Once today's price is at least as high as some earlier day, that earlier day can never be the stopper for anyone later: today is closer and just as tall. So pop it for good. After popping, the top of the stack is the stopper, and the span is the distance to it.

Here the answer goes to the arriving day, computed from whatever is left on top after the pops.

Time O(n)Space O(n)Walk back from each day: O(n²)
Problem 4 · Both sides at once

Largest rectangle in a histogram

Question

A histogram has bars of width 1 with the given heights, standing side by side. Find the area of the largest rectangle that fits entirely inside the bars.

Input[2, 1, 5, 6, 2, 3]
Output10 (height 5 across the bars 5 and 6)
Think first: if bar j is the shortest bar of the rectangle, how wide can it be?

The best rectangle has some shortest bar j, and it stretches from the nearest shorter bar on the left to the nearest shorter bar on the right. Keep an increasing stack. When a shorter bar arrives at i, it is the right wall for the bar it pops; the new top of the stack is the left wall. Width = i − left − 1. A height-0 bar at the end flushes everything left on the stack.

Read the picture: amber bars are on the stack (heights rise from bottom to top). The red bar is being popped and the blue shaded box is the rectangle it measures. The green dashed outline is the best rectangle so far.

Time O(n)Space O(n)Try every pair of walls: O(n²)
Correctness

Why one pass is enough, and why it's linear

Invariant

For next greater (Problem 1), the stack holds exactly the indices seen so far that haven't met a bigger value, and their values never increase from bottom to top. A new value pops only from the top, so the order survives every push.

Pops are correct

When x pops index j, everything pushed between j and now was either popped by something no bigger than a[j] or still sits above j, so nothing in between was bigger than a[j]. x is the first bigger value. That is the answer, not just an answer.

Pops are safe

For "previous greater" (Problem 3), a popped index j has a[j] ≤ x. Any later element that would stop at j would stop at i first, because i is closer and at least as tall. So j can be thrown away forever.

Amortized O(n)

The inner while loop can run many times for one i, which looks quadratic. But each index is pushed exactly once and popped at most once, so across the whole run there are at most n pushes and n pops: at most 2n stack operations in total. The steppers above count them for you.

In an interview

Name the stack's order ("values decreasing from bottom to top"), say what a pop means ("the arriving element answers the popped one"), and give the push-once, pop-once argument for O(n). Then mention how ties are handled (< or <=).

pushes ≤ n, pops ≤ pushes ⇒ total work ≤ 2n = O(n)
