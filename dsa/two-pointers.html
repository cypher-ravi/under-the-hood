Two Pointers

Put one finger at each end of an array and walk them toward each other. Every move rules out one element for good, so you find a pair in a single pass instead of checking every pair.

In 30 seconds
  • What: two indices, L and R, moving through the same array.
  • When: the array is sorted, or the question is about a pair, or about both ends of something.
  • Why it's fast: each step throws one element away forever, so n elements take at most n steps. O(n) instead of O(n²).
  • The one thing to get right: which pointer to move, and a one-sentence reason why that's safe.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, by example

Find two numbers that add up to 10

Here is a sorted list. We want two numbers from it that add up to exactly 10.

Start with the smallest (L) and the largest (R) and add them. Then ask one question: which of these two can never be part of the answer?

LRSumWhat it tells us
11112Too big. 11 is too big even with the smallest number, so 11 is out. Move R left.
189Too small. 1 is too small even with the biggest number left, so 1 is out. Move L right.
3811Too big. 8 is out. Move R left.
369Too small. 3 is out. Move L right.
4610Found it.

Five looks. Checking every pair would take 15. With 10,000 numbers the gap becomes 10,000 looks versus about 50 million, because two nested loops check n(n−1)/2 pairs.

The trick is not the two pointers. It's that the sorted order lets one comparison rule out a whole element, so you never come back to it.

Recognizing the pattern

Signals in the problem statement

Reach for two pointers when you see one or more of these:

  • The input is sorted, or sorting it doesn't change the answer.
  • You're looking for a pair (or a triple) that meets a condition, like a target sum.
  • The answer depends on both ends of something: palindromes, reversing, the width between two walls.
  • You must work in place or with O(1) extra memory.

When not to: if you must return original positions from unsorted data, sorting scrambles them. A hash map ("have I seen target − x?") is the better tool there, at the cost of O(n) memory.

Template

The skeleton you adapt

L, R = 0, len(a) - 1
while L < R:
    if found(a[L], a[R]):
        return answer
    if a[L] can't be in any answer:
        L += 1
    else:   # then a[R] can't be
        R -= 1

To adapt it to a new problem, answer three questions:

  1. Where do the pointers start? Usually both ends. Sometimes both at the start (see Sliding Window).
  2. What do you check at each step? A sum, a pair of characters, an area.
  3. Which pointer moves, and why is that safe? Say it in one sentence, like "the sum is too small, so a[L] is too small even with the largest partner". That sentence is what interviewers listen for.
Problem 1 · Mirror

Is it a palindrome?

Question

Given a string, return true if it reads the same forwards and backwards, ignoring case and any character that isn't a letter or digit.

Input"No lemon, no melon"
Outputtrue
Whyletters only: nolemonnomelon

What must be true about the first and last letters of a palindrome?

The obvious way

Build a cleaned, lowercase copy of the string, reverse it, and compare. It works, but the copy costs O(n) extra memory.

Key insight

A palindrome is a mirror. The first real character must match the last, the second must match the second-to-last, and so on. Check those pairs from the outside in, skipping punctuation as you go.

The plan

  1. Put L on the first character and R on the last.
  2. If L is on a space or punctuation, move it right. Same for R, moving left.
  3. Compare the two characters, ignoring case. Different? Return false.
  4. Same? Move both inward. If the pointers meet, every pair matched: return true.

Watch it run

Press Next to step through, or type your own string. Green pairs matched; amber characters were skipped.

Problem 2 · Rule one out

Pair with a target sum in a sorted array

Question

Given an array sorted in increasing order and a target, return the indices of two different elements that add up to the target, or report that none exist.

Input[1, 3, 4, 6, 8, 11], target 10
Output[2, 3] (4 + 6)

If the smallest plus the largest is too small, which of the two is hopeless?

The obvious way

Two nested loops try every pair. That's n(n−1)/2 checks, and it ignores the fact that the array is sorted.

Key insight

If a[L] + a[R] is too small, a[L] is too small even with the biggest partner available, so it can't be in any answer: drop it. If the sum is too big, a[R] is too big even with the smallest partner: drop it.

The plan

  1. L at the smallest element, R at the largest.
  2. Add them. Equal to the target? Return [L, R].
  3. Too small: move L right. Too big: move R left.
  4. If L and R meet, no pair exists.

Watch it run

The grid shows every possible pair (row = L, column = R). Each step crosses off a whole row or column at once; the dark cell is the pair being checked.

Time O(n)Space O(1)Every pair: O(n²)

Using this on an unsorted array. The "drop it" argument needs sorted order; sort first, or use a hash map if you need the original indices.

Problem 3 · Rule one out

Container with the most water

Question

Each number is the height of a vertical wall, one unit apart. Pick two walls. Together with the ground they hold water up to the shorter wall. Return the largest amount of water any pair can hold.

Input[1, 8, 6, 2, 5, 4, 8, 3, 7]
Output49 (walls 1 and 8: min(8, 7) × 7)

Water = shorter wall × distance. Which wall is holding the water back?

The obvious way

Try every pair of walls, compute the water, keep the best. O(n²).

Key insight

Start with the widest pair. The shorter wall is the bottleneck. Any other container that uses it is narrower and still capped by that same short wall, so it can only hold less. The short wall has already given its best answer: drop it.

The plan

  1. L at the first wall, R at the last. Best so far = 0.
  2. Water = min(h[L], h[R]) × (R − L). Keep it if it beats the best.
  3. Move the pointer on the shorter wall inward (either one if they're equal).
  4. Stop when they meet. Return the best.

Watch it run

Time O(n)Space O(1)Every pair: O(n²)

Moving the taller wall. That only shrinks the width while the height stays capped, so it can never help.

Problem 4 · Fix one, then two pointers

All triplets that sum to zero

Question

Given an array of integers, return every distinct triplet of values that adds up to zero. Each triplet should appear only once.

Input[-1, 0, 1, 2, -1, -4]
Output[[-1, -1, 2], [-1, 0, 1]]

If you already knew the first number, what problem would be left?

The obvious way

Three nested loops try every triplet, then a set removes duplicates. O(n³).

Key insight

Sort, then fix the first number a[i]. You now need two numbers after it that add up to −a[i]. That's exactly Problem 2, which takes one pass.

The plan

  1. Sort the array.
  2. For each i: if a[i] equals the previous value, skip it (same triplets again).
  3. Run Problem 2 on the part after i, looking for −a[i].
  4. On a hit, record it, move L right, and skip any repeats of the old a[L].

Watch it run

Time O(n²)Extra space O(1) besides the outputEvery triplet: O(n³)

Forgetting to skip repeated values, which reports [-1, 0, 1] twice.

Correctness

Why you never skip the answer

The whole argument fits in three sentences:

Always true

If an answer exists, it's inside the range from L to R. At the start the range is the whole array, so this holds.

Each step

We only move a pointer after showing its element can't pair with anything left. So the answer is still inside the range after the move.

It ends

Every step shrinks the range by one, so there are at most n − 1 steps. That's the O(n).

In an interview: say the "always true" line out loud, then give the one-line reason for each move. Interviewers look for that argument more than for the code.

Recap

Cheat sheet

Palindrome

Compare ends, move both inward. Skip non-letters.

Pair sum (sorted)

Too small → L++. Too big → R−−.

Most water

Move the shorter wall. It's the bottleneck.

Three sum

Sort, fix i, pair sum on the rest. Skip repeats.
