Two Pointers

Keep two indices into the same array and move them toward each other, or together, based on what you see. Each step throws away at least one element for good, so a problem that looks like it needs every pair can be solved in a single pass.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

Why two indices beat a double loop

Many array problems ask about pairs: two numbers that add to a target, two walls that hold the most water, two characters that should match. The obvious approach checks every pair with two nested loops, which is n(n−1)/2 checks. For 10,000 elements that is about 50 million.

Two pointers works when the array has an order you can exploit, such as sorted values or mirrored positions. Then one comparison tells you which pointer can never be part of the answer, so you move it and never look back. Each step retires one element, so the whole scan takes at most n steps.

Three ways the pattern shows up

Direct

Pointers start at both ends and walk inward, comparing mirrored positions. There is no decision to make; both always move.

Problem 1: Palindrome check

Reduction

On sorted data, compare the pair against a goal and move only the pointer that cannot help. This turns an O(n²) search into O(n).

Subproblem

Fix one element with an outer loop, then solve the rest as a two-pointer reduction. Three-element problems become O(n²) instead of O(n³).

Recognizing the pattern

Signals in the problem statement

  • The input is a sorted array, or sorting it doesn't break the question.
  • You are looking for a pair (or a triple) that meets a condition such as a target sum.
  • The answer depends on both ends of a range: palindromes, reversing, widths between walls.
  • You are asked to do it in place or with O(1) extra memory. A hash map would also work for many pair problems, but uses O(n) space.

Counter-signal: if the order of elements matters and you can't sort (for example "return the original indices" on unsorted data), a hash map is usually the better tool.

Template

The skeleton you adapt

L, R = 0, len(a) - 1
while L < R:
    # look at a[L] and a[R]
    if found(a[L], a[R]):
        return answer
    if a[L] can't be part of any answer with anything in a[L+1..R]:
        L += 1
    else:                  # then a[R] can't be part of any answer
        R -= 1

The only thing that changes between problems is the rule for which side to discard. Your job in an interview is to state that rule and prove it. The proof is usually one sentence about sorted order.

Problem 1 · Direct

Is it a palindrome?

Question

Given a string, return true if it reads the same forwards and backwards, ignoring case and any character that isn't a letter or digit.

Input"No lemon, no melon"
Outputtrue
Whyletters only: nolemonnomelon
Think first: what do the two ends tell you?

The first real character must equal the last real character, the second must equal the second-to-last, and so on. Walk inward from both ends and skip anything that isn't a letter or digit. You never need to build a cleaned copy of the string.

Time O(n)Space O(1)Cleaning into a new string first: O(n) space
Problem 2 · Reduction

Pair with a target sum in a sorted array

Question

Given an array sorted in increasing order and a target, return the indices of two different elements that add up to the target, or report that none exist.

Input[1, 3, 4, 6, 8, 11], target 10
Output[2, 3] (4 + 6)
Think first: if the sum is too small, what can you rule out?

If a[L] + a[R] is less than the target, then a[L] plus any element at or before R is also too small, because a[R] is the largest of them. So a[L] can't be in any answer. Move L right. The same logic in reverse rules out a[R] when the sum is too large.

Read the grid: each cell is one pair (row = L, column = R). Two nested loops would visit every cell in the upper triangle. Each two-pointer step crosses off a whole row or column at once, and the dark cell is the pair being checked.

Time O(n)Space O(1)Brute force: O(n²) pairs
Problem 3 · Reduction

Container with the most water

Question

Each number is the height of a vertical wall, one unit apart. Pick two walls. Together with the ground they hold water up to the shorter wall. Return the largest amount of water any pair can hold.

Input[1, 8, 6, 2, 5, 4, 8, 3, 7]
Output49 (walls 1 and 8: min(8, 7) × 7)
Think first: which wall is safe to give up?

Start with the widest pair. The water is limited by the shorter wall. Moving the taller wall inward can only make the width smaller while the height stays capped by the same short wall, so it can never help. The shorter wall has already given its best possible answer, so discard it.

Time O(n)Space O(1)Brute force: O(n²)
Problem 4 · Subproblem

All triplets that sum to zero

Question

Given an array of integers, return every distinct triplet of values that adds up to zero. Each triplet should appear only once.

Input[-1, 0, 1, 2, -1, -4]
Output[[-1, -1, 2], [-1, 0, 1]]
Think first: how do you turn three into two?

Sort the array. Fix the first number a[i]. You now need two numbers after it that sum to −a[i], which is exactly Problem 2. Skip equal neighbours for i and L so each triplet is reported once.

Time O(n²)Extra space O(1) besides the outputBrute force: O(n³)
Correctness

Why you never skip the answer

Invariant

If an answer exists, it lies inside the current range [L, R]. It's true at the start, when the range is the whole array.

Each step

A pointer moves only after we've shown its element pairs with nothing left in the range. So the answer is still inside [L, R] after the move.

Termination

Every step shrinks the range by one, so the loop ends after at most n − 1 steps. That's the O(n).

In an interview

Say the invariant out loud, then give the one-line reason for each move. Interviewers look for that argument more than the code.
