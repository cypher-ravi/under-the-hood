Interval Merging and Overlap

An interval is a start and an end: a meeting, a booking, a range of pages. Problems about many intervals look tangled until you sort them. Once they're in order of start time, each interval can only collide with the one just before it, and a single left-to-right pass answers merge, insert and overlap questions. Turn starts and ends into events and the same pass counts how many intervals are open at once.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

Sorted by start, overlap is a local question

Two intervals [a, b] and [c, d] overlap when each starts before the other ends: a ≤ d and c ≤ b. Checking every pair takes n² comparisons. Sorting removes most of that work.

If the intervals are sorted by start, then a ≤ c is already known, so overlap shrinks to one check: c ≤ b, "does the next one start before the current one ends?" And if the next interval doesn't overlap the block you've built so far, no later interval can either, because later ones start even further right. So you only ever compare the next interval with the last block. Sorting costs n log n, and the pass costs n.

Recognizing the pattern

Signals in the problem statement

  • The input is a list of pairs with a start and an end: times, dates, ranges, segments on a line.
  • The question uses words like overlap, conflict, merge, free time, at the same time or how many at once.
  • A brute force compares every pair, and the expected answer is O(n log n): a strong hint that sorting comes first.
  • You must pick the most non-clashing intervals or remove the fewest: sort by end and be greedy.

The three cases for two intervals, once sorted by start

Watch the edges: do [1, 3] and [3, 5] overlap? For merging ranges of numbers, usually yes (they share 3). For meetings, usually no (one ends as the other starts). Ask, then pick ≤ or < to match. The problems below say which they use.

Template

The skeleton you adapt

intervals.sort(key=lambda x: x[0])       # by start (by end for greedy)
out = [intervals[0]]
for start, end in intervals[1:]:
    last = out[-1]
    if start <= last[1]:                  # overlaps the last block
        last[1] = max(last[1], end)      # combine
    else:
        out.append([start, end])         # a gap: start a new block
# sweep variant: events = (start, +1) and (end, -1), sort, running sum

Problems differ in the sort key and in what "combine" means: extend the block (merge), count it (rooms), or throw one away (removals). The most common bug is last[1] = end instead of max(last[1], end), which breaks when one interval sits entirely inside another.

Problem 1 · Merge

Merge overlapping intervals

Question

Given a list of intervals in any order, combine every group that overlaps or touches, and return the resulting intervals sorted by start.

Input[[8, 10], [1, 3], [2, 6], [15, 18]]
Output[[1, 6], [8, 10], [15, 18]]
Think first: after sorting, who can the next interval collide with?

Only the last block in the output. Every earlier block ends before the last one starts, and the next interval starts after the last one starts. So compare its start with the last block's end: extend if it's not past it, otherwise start a new block.

Time O(n log n)Space O(n) for the outputCompare all pairs: O(n²), and still needs repeated passes
Problem 2 · Insert

Insert an interval

Question

You have a calendar of busy intervals that are already sorted and don't overlap. Add one new interval, merging wherever needed, and return the calendar still sorted and non-overlapping.

Inputbusy = [[1, 2], [3, 5], [6, 7], [8, 10], [12, 16]], new = [4, 8]
Output[[1, 2], [3, 10], [12, 16]]
Think first: do you need to sort again?

No. The list splits into three runs: intervals that end before the new one starts (copy them), intervals that overlap it (absorb them by widening the new interval), and intervals that start after it ends (copy them). One pass, O(n).

Time O(n)Space O(n) for the outputAppend and re-run merge: O(n log n)
Problem 3 · Sweep

How many meeting rooms?

Question

Each interval is a meeting [start, end). A room is free again the moment a meeting ends, so [1, 4) and [4, 6) can share. What's the smallest number of rooms that fits every meeting?

Input[[0, 30], [5, 10], [15, 20], [10, 15]]
Output2
Think first: what's the answer, in terms of a single moment?

The rooms needed equals the most meetings running at the same instant. Walk through time: each start opens a room (+1), each end frees one (−1). Sort these events, and at equal times put ends before starts so a freed room can be reused. The highest running total is the answer.

Time O(n log n)Space O(n) for the eventsCheck every time point against every meeting: O(n × range)
Problem 4 · Greedy by end

Fewest intervals to remove

Question

Remove as few intervals as possible so that the rest don't overlap. Intervals that only touch, like [1, 2] and [2, 3], are fine. Return how many you removed.

Input[[1, 2], [2, 3], [3, 4], [1, 3]]
Output1 (remove [1, 3])
Think first: which interval is always safe to keep?

The one that ends earliest. Whatever the best answer keeps first, swapping it for the earliest-ending interval can't cause a new clash, because it ends no later. So sort by end, keep an interval if it starts at or after the last kept end, and remove it otherwise.

Time O(n log n)Space O(1) besides sortingTry every subset: O(2ⁿ)
Correctness

Why one pass after sorting is enough

Invariant

After handling the first k intervals in sorted order, the output holds the correct merged blocks for those k, and only the last block can still grow.

Each step

The next interval starts at or after every earlier start. If it starts after the last block ends, a gap separates them, and since later intervals start even further right, nothing can ever bridge that gap.

Sweep

The count of open intervals only changes at a start or an end, so checking just those event times finds the true maximum. Ends sort first at ties because a half-open interval has already finished.

Greedy

An exchange argument: replacing the first interval of any best answer with the earliest-ending one keeps it valid and the same size. Repeat on what's left.

History

Sweeping a line across a set of objects, handling them as events in sorted order, was popularized by Michael Shamos and Dan Hoey's 1976 work on geometric intersection problems. The rooms problem is that sweep in one dimension.
