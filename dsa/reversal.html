In-place Reversal

Reverse a linked list by turning each arrow around as you walk past it. Three pointers do the whole job in one pass, with no new nodes and no copy.

In 30 seconds
  • What: three pointers, prev, curr and nxt, walk the list and flip each next arrow backwards.
  • When: a singly linked list needs to be reversed, whole or in pieces, without extra memory.
  • Why it's fast: each node is visited once and flipped once. O(n) time, O(1) extra memory.
  • The one thing to get right: save curr.next before you overwrite it. For a piece of the list, also reconnect both ends.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, by example

Reverse 4 → 9 → 2 → 7 → 5

In a linked list each node only knows the node after it (its next arrow). To reverse the list, every arrow must point the other way: 9 should point to 4, 2 to 9, and so on.

The danger: once you point 4's arrow somewhere else, you've lost the only way to reach 9. So before each flip, save the next node. Then flip, then step forward.

currReversed so farWhat happens
44Save 9. Point 4 at nothing. Step to 9.
99 → 4Save 2. Point 9 at 4. Step to 2.
22 → 9 → 4Save 7. Point 2 at 9. Step to 7.
77 → 2 → 9 → 4Save 5. Point 7 at 2. Step to 5.
55 → 7 → 2 → 9 → 4Point 5 at 7. Nothing left: 5 is the new head.

At every moment the list is two clean pieces. Here it is after two rows: the reversed piece 9 → 4 (shaded) and the untouched piece 2 → 7 → 5.

Reversing is easy. Not losing the rest of the list is the whole trick: save the next node, flip one arrow, slide forward. Each node moves from the untouched piece to the reversed piece exactly once.

Recognizing the pattern

Signals in the problem statement

Reach for in-place reversal when you see one or more of these:

  • The input is a singly linked list and the answer needs it, or part of it, in reverse order.
  • The problem says "in place", "without extra memory" or "O(1) space", which rules out an array copy or a stack.
  • It talks about positions or groups: "from position 2 to 5", "every k nodes", "swap pairs".
  • You need to read a list back to front, for example to compare its two ends.

When not to: if you only need to read values backwards and memory is fine, a stack or recursion is simpler and leaves the list alone. Reversing in place changes the input. Say so in an interview, and put it back if the caller still needs it.

Template

The skeleton you adapt

prev, curr = None, head
while curr:
    nxt = curr.next   # save the rest
    curr.next = prev  # flip
    prev = curr       # grow reversed
    curr = nxt        # step on
return prev           # new head

To adapt it to a new problem, answer three questions:

  1. Where does the reversal start? At the head, or right after a node before. Put a dummy node in front of the head so before always exists, even when the piece starts at the head.
  2. How long does the loop run? Until curr is None for the whole list, or exactly k times for a piece of length k.
  3. How do you reconnect the ends? After the loop, prev is the piece's new first node and curr is the node after it. Point before at prev, and the piece's old first node (now its last) at curr.
Problem 1 · Whole list

Reverse a linked list

Question

Given the head of a singly linked list, reverse it by changing the links between nodes, and return the new head. Don't create new nodes or copy the values elsewhere.

Input4 → 9 → 2 → 7 → 5
Output5 → 7 → 2 → 9 → 4
Edge casean empty list or one node comes back unchanged

If you set curr.next = prev right away, how do you get to the next node?

The obvious way

Copy the values into an array, then write them back in reverse order (or build a new list). It works, but it costs O(n) extra memory, which the question rules out.

Key insight

Flipping an arrow cuts the only link to the rest of the list, so store curr.next in nxt first. When curr finally runs off the end, prev sits on the old last node, which is the new head.

The plan

  1. Start with prev = None and curr = head.
  2. Save nxt = curr.next.
  3. Flip: curr.next = prev.
  4. Slide: prev = curr, curr = nxt. Repeat while curr exists.
  5. Return prev.

Watch it run

Press Next to step through, or type your own list. P, C and N mark prev, curr and nxt. Blue arrows have been flipped; shaded nodes are the reversed piece.

Time O(n)Space O(1)Recursive version: O(n) call stack

Returning head at the end. The old head is now the tail and points to nothing; the new head is prev.

Problem 2 · A piece

Reverse positions left to right

Question

Given the head of a linked list and two positions left ≤ right (counting from 1), reverse only the nodes from position left through right, leaving the rest in place. Do it in one pass.

Input1 → 2 → 3 → 4 → 5 → 6, left = 2, right = 5
Output1 → 5 → 4 → 3 → 2 → 6

After the piece 2 → 3 → 4 → 5 is reversed, which two arrows still point the wrong way?

The obvious way

Copy the values in the piece into an array, reverse the array, and write the values back. That's two passes and O(k) extra memory for a piece of k nodes.

Key insight

Run the usual flip loop exactly right − left + 1 times. The piece comes out reversed but detached: the node before it still points at its old first node, and that node now points at nothing useful. Two stitches fix it. A dummy node in front makes left = 1 work like any other case.

The plan

  1. Put a dummy in front of head. Walk before from the dummy left − 1 steps.
  2. Run the flip loop right − left + 1 times, starting at before.next.
  3. tail = before.next: the piece's old first node, now its last.
  4. Stitch: before.next = prev and tail.next = curr.
  5. Return dummy.next.

Watch it run

D is the dummy. B marks before, T the tail, and P, C, N are prev, curr and nxt. The shaded nodes are the piece being reversed. Watch the two stitch steps near the end.

Time O(n)Space O(1)Copy the piece to an array: O(k) space

Skipping the dummy node. When left = 1 there is no node before the piece, so the code crashes or returns the old head.

Problem 3 · A piece, repeated

Reverse every group of k nodes

Question

Given a linked list and a whole number k, reverse the nodes in consecutive groups of k. If the last group has fewer than k nodes, leave it as it is. Use constant extra memory.

Input1 → 2 → 3 → 4 → 5 → 6 → 7 → 8, k = 3
Output3 → 2 → 1 → 6 → 5 → 4 → 7 → 8

Each group is one Problem 2. After you finish a group, which node is "before" the next one?

The obvious way

Copy each group's values into an array, reverse them, write them back. That needs O(k) memory. A recursive version uses a call stack that grows with the number of groups.

Key insight

Treat each group as a Problem 2 piece. Before flipping anything, send a probe k steps ahead to check the group is full. After stitching, the group's old first node is now its last, so it becomes before for the next group.

The plan

  1. Dummy in front; before = dummy.
  2. Probe k nodes ahead. If the list runs out, return dummy.next.
  3. Reverse those k nodes and stitch both ends, as in Problem 2.
  4. Move before to the group's new last node. Repeat.

Watch it run

B is before and Z is the probe that checks k nodes remain. P, C, N are prev, curr, nxt; T is the tail. The shaded nodes are the current group.

Time O(n)Space O(1)Each node is probed once and flipped once: about 2n steps

Reversing the short last group too. Probe first, and stop before flipping anything if fewer than k nodes remain.

Problem 4 · As a helper

Is the linked list a palindrome?

Question

Given the head of a singly linked list of numbers, decide whether the values read the same forwards and backwards. Use O(1) extra memory, so no copying the values into an array.

Input3 → 1 → 4 → 1 → 3
Outputtrue
Input3 → 1 → 4 → 4 → 2
Outputfalse

A palindrome check compares the two ends. How do you walk a singly linked list from the back?

The obvious way

Copy the values into an array and run the two-pointer palindrome check. Simple, but O(n) extra memory.

Key insight

Make the back half walkable from the end by reversing it. Find the middle with slow and fast pointers, reverse from the middle to the end, then walk one pointer from the head and one from the old tail, comparing as you go.

The plan

  1. Move slow one step and fast two steps until fast can't go on. slow is at the middle.
  2. Reverse the list from slow to the end.
  3. Walk a from the head and b from the new back head. Any mismatch: return false.
  4. When b runs out, return true. If the caller still needs the list, reverse the back half again first.

Watch it run

Three phases. S and F are slow and fast; P and C reverse the back half; A and Z walk from the front and back, green when they match.

Time O(n)Space O(1)Copy into an array: O(n) space

Looping while the front walker exists. On an even-length list the front half is one node longer, so loop until the back walker runs out.

Correctness

Why no node gets lost

The whole argument is about the two pieces from the idea section:

Always true

prev heads the nodes already visited, linked in reverse. curr heads the nodes not yet visited, still in order. Every node is in exactly one piece. At the start the reversed piece is empty, so this holds.

Each step

Save, flip, slide moves exactly one node from the front of the untouched piece to the front of the reversed piece. Nothing else changes, so the statement above still holds.

It ends

The untouched piece loses one node per step, so the loop stops after n steps (or k for a piece). Then everything is in the reversed piece, headed by prev.

For a piece

The same holds inside the piece. The two stitches then reconnect three parts: before → reversed piece → rest of the list.

In an interview: draw the two pieces and say the "always true" line out loud. Then mention the dummy node for pieces that start at the head, and that the input list is changed.

Cheat sheet

Reverse a list

Save next, flip, slide. Return prev.

Reverse left to right

Dummy, walk to before, flip k times, two stitches.

Every k nodes

Probe k ahead first. Old first node becomes the next before.

Palindrome list

Find the middle, reverse the back half, compare inward.
