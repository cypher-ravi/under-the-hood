In-place Reversal

Reverse a linked list, or a piece of one, by turning each next arrow around as you walk past it. Three pointers do the whole job: the node behind you, the node you're on, and the node ahead that you must remember before you cut its link. No new nodes, no array copy, O(1) extra memory.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

Flip one arrow at a time, without losing the rest

In a singly linked list each node knows only its successor. To reverse the list, every arrow must point the other way: node 2 should point to node 1, node 3 to node 2, and the old head to nothing. You could copy the values into an array and rebuild, but that costs O(n) memory, and the question usually forbids it.

The catch with flipping in place is that the moment you set curr.next = prev, you've cut the only link to the rest of the list. So save it first: nxt = curr.next. Then flip, then slide both prev and curr one node forward. Every node is visited once, and at any moment the list is two clean pieces: an already-reversed piece headed by prev, and an untouched piece headed by curr.

Recognizing the pattern

Signals in the problem statement

  • The input is a singly linked list and the answer needs it (or part of it) in reverse order.
  • The problem says "in place", "without extra memory" or "O(1) space", ruling out a stack or an array copy.
  • It talks about positions or groups: "from position m to n", "every k nodes", "pairs".
  • You need to read a list back to front (compare ends, interleave first and last), and a stack isn't allowed.

Counter-signal: if you only need to print or read values backwards and memory is fine, recursion or a stack is simpler and leaves the list intact. Reversing in place modifies the input; say so in an interview, and restore it if the caller still needs it.

Template

The skeleton you adapt

prev, curr = None, head
while curr:                   # or: for _ in range(segment_length)
    nxt = curr.next           # 1. remember the rest of the list
    curr.next = prev          # 2. flip this arrow
    prev = curr               # 3. the reversed part grows by one
    curr = nxt                # 4. step into the untouched part
return prev                   # new head of the reversed part

For a segment, add two things. A dummy node in front of the head, so "the node before the segment" always exists, even when the segment starts at position 1. And a stitch after the loop: the node before the segment must point to prev (the segment's new first node), and the segment's old first node, now its last, must point to curr (the first node after it).

Problem 1 · Whole list

Reverse a linked list

Question

Given the head of a singly linked list, reverse it by changing the links between nodes, and return the new head. Don't create new nodes or copy the values elsewhere.

Input4 → 9 → 2 → 7 → 5
Output5 → 7 → 2 → 9 → 4
Edge casean empty list or one node comes back unchanged
Think first: what do you lose if you flip before saving?

Setting curr.next = prev overwrites the only reference to the rest of the list. Store curr.next in a temporary first; then the flip is safe. When curr runs off the end, prev is on the old last node, the new head.

Time O(n)Space O(1)Recursive version: O(n) call stack
Problem 2 · A segment

Reverse positions left to right

Question

Given the head of a linked list and two positions left ≤ right (counting from 1), reverse only the nodes from position left through right, leaving the rest in place. Do it in one pass.

Input1 → 2 → 3 → 4 → 5 → 6, left = 2, right = 5
Output1 → 5 → 4 → 3 → 2 → 6
Think first: which two links change at the edges?

Reverse the segment with the usual loop, run exactly right − left + 1 times. Afterwards prev is the segment's new first node and curr is the node just after it. The node before the segment must now point to prev, and the old first node of the segment (now its last) must point to curr. A dummy node in front handles left = 1.

Time O(n)Space O(1)Copy segment to an array: O(k) space
Problem 3 · Repeated segments

Reverse every group of k nodes

Question

Given a linked list and a whole number k, reverse the nodes in consecutive groups of k. If the last group has fewer than k nodes, leave it as it is. Use constant extra memory.

Input1 → 2 → 3 → 4 → 5 → 6 → 7 → 8, k = 3
Output3 → 2 → 1 → 6 → 5 → 4 → 7 → 8
Think first: what does Problem 2 give you for free?

Each group is a Problem 2 segment. Before reversing, check that k nodes remain ahead; if not, stop. After stitching a group, its old first node is now its last, which makes it the "node before" the next group. Move before there and repeat.

Time O(n)Space O(1)Each node is counted once and flipped once: about 2n steps
Problem 4 · Reversal as a helper

Is the linked list a palindrome?

Question

Given the head of a singly linked list of numbers, decide whether the values read the same forwards and backwards. Use O(1) extra memory, so no copying the values into an array.

Input3 → 1 → 4 → 1 → 3
Outputtrue
Input3 → 1 → 4 → 4 → 2
Outputfalse
Think first: how do you walk the back half backwards?

Find the middle with fast and slow pointers. Reverse the list from the middle to the end. Now one pointer from the head and one from the old tail walk toward each other, comparing values. The back half is never longer than the front, so stop when the back pointer runs out.

Be a polite caller: this modifies the input list. Reverse the back half again before returning if anyone else holds the list. It's one more O(n) pass and keeps the O(1) memory.

Time O(n)Space O(1)Copy into an array: O(n) space
Correctness

One invariant carries every variant

Invariant

Before each pass of the loop, prev heads the nodes already visited, linked in reverse order, and curr heads the nodes not yet visited, still in their original order. No node is in both pieces and none is lost.

Step

Saving nxt, flipping curr.next to prev and sliding both pointers moves exactly one node from the front of the untouched piece to the front of the reversed piece. The invariant still holds.

End

The untouched piece shrinks by one each pass, so the loop ends after n passes (or k for a segment). Then the reversed piece is everything, in reverse, headed by prev.

Segments

For a segment, the invariant holds inside it, and the two stitches reconnect the three pieces: before → reversed segment → after. Getting those two links right is the whole difference between Problems 1 and 2.

In an interview

Draw three boxes and say the invariant out loud. Then mention the dummy node for segments that start at the head, and that the input is modified.
