DFS and BFS on Trees

A tree problem almost always comes down to visiting every node once in a sensible order. Depth-first search follows one branch all the way down before backing up, and the call stack remembers the way back. Breadth-first search sweeps the tree one level at a time with a queue. Pick the order that hands each node the information it needs, and most tree questions turn into a few lines of code.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

A tree is a node plus two smaller trees

A binary tree is either empty or a node with a value, a left subtree and a right subtree. That definition is recursive, so the natural way to process a tree is too: handle the node, and ask the same function to handle each subtree. The empty tree is the base case, where there is nothing to do.

That leaves one real decision: when you do the work for a node relative to its children. Before both (preorder), between them (inorder), or after both (postorder). Or forget about subtrees and go level by level from the top (level order). Every node is visited exactly once in all four, so each runs in O(n). What changes is what you know at the moment you handle a node.

Three ways the pattern shows up

Order matters

The output is the visiting order itself, or the order is what makes the answer easy, like the sorted order an inorder walk gives on a search tree.

Recognizing the pattern

Signals in the problem statement

  • The input is a tree (or something tree-shaped: folders, an org chart, a parsed expression) and the answer needs every node or every root-to-leaf path.
  • The answer for a node can be built from the answers for its children: height, size, sum, balanced or not. That's a postorder DFS that returns values.
  • Each node needs something from above: the path so far, a running sum, the range its value must fall in. Pass it down as an argument (preorder style).
  • The words level, row, depth from the top, closest to the root, or "the view from the right side". That's BFS with a queue.
  • The tree is a binary search tree and you need values in sorted order, the k-th smallest, or neighbours in value. That's inorder.

Watch the depth: recursion uses one stack frame per level. A balanced tree of a million nodes is about 20 levels deep, but a tree that is really a linked list is a million levels deep, and Python stops at about 1,000 by default. If the input can be that lopsided, use the iterative version with an explicit stack.

Template

Three skeletons: recursive DFS, iterative DFS, BFS

DFS, recursive

def dfs(node):
    if node is None:
        return            # empty tree: base case
    # preorder work here
    dfs(node.left)
    # inorder work here
    dfs(node.right)
    # postorder work here

DFS, iterative (preorder)

stack = [root] if root else []
while stack:
    node = stack.pop()
    visit(node)
    if node.right: stack.append(node.right)
    if node.left:  stack.append(node.left)
# left pushed last, so popped first

BFS, one level at a time

from collections import deque
q = deque([root]) if root else deque()
while q:
    # the queue now holds exactly one level
    for _ in range(len(q)):
        node = q.popleft()
        visit(node)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)

The recursive DFS is the one to reach for first: put the work where the node has what it needs. The iterative version does the same walk with a list you manage yourself, which is exactly what the call stack does for you in the recursive one. BFS swaps the stack for a queue: first in, first out, so nodes come out in order of depth.

Two habits prevent most bugs. Handle the empty tree first, both at the top and as the base case. And for BFS, read len(q) before the inner loop, so the children you add during this level wait for the next one.

Problem 1 · Order matters

Preorder, inorder and postorder

Question

Given the root of a binary tree, return its node values in preorder (node, then left subtree, then right subtree), inorder (left, node, right) and postorder (left, right, node).

Input[1, 2, 3, 4, 5, null, 6]
Preorder[1, 2, 4, 5, 3, 6]
Inorder[4, 2, 5, 1, 3, 6]
Postorder[4, 5, 2, 6, 3, 1]
Think first: do you need three different functions?

No. All three make the same calls in the same order: the node, then everything on its left, then everything on its right. The only difference is which line appends the value: before the left call, between the two calls, or after the right call. Step through and watch the call stack: it is identical for all three orders.

Blue = the running call. Amber = paused on the call stack, waiting for a child. Green ring = call finished. Dashed ∅ = a call on an empty child.

Time O(n)Space O(h) for the stackSkewed tree: h = n
Problem 2 · Level by level

Level order traversal

Question

Given the root of a non-empty binary tree, return its values level by level: a list of lists where the first list holds the root, the next holds its children from left to right, and so on.

Input[3, 9, 20, null, null, 15, 7]
Output[[3], [9, 20], [15, 7]]
Think first: how do you know where one level ends?

Use a queue. When you start a level, the queue holds exactly the nodes of that level and nothing else, so its current length is the size of the level. Pop that many nodes, adding their children to the back. The children pile up behind the current level and become the next one.

Blue = the node just popped. Amber = waiting in the queue. Green ring = already added to a level.

Time O(n)Space O(w), w = widest levelFull tree: w ≈ n / 2
Problem 3 · Bottom-up DFS

Maximum depth of a binary tree

Question

Return the number of nodes on the longest path from the root down to a leaf. An empty tree has depth 0 and a single node has depth 1.

Input[3, 9, 20, null, null, 15, 7]
Output3 (3 → 20 → 15)
Think first: if you knew the depths of both subtrees, what is the answer?

One more than the deeper of the two. So ask each child for its depth, wait for both answers, then return 1 + max(left, right). The work happens after both calls, which makes this a postorder walk. The empty tree answers 0, and that stops the recursion.

The number under a finished node is the depth its call returned. At the end, filled green nodes mark one deepest path.

Time O(n)Space O(h)BFS also works: count the levels
Problem 4 · Top-down DFS

Is it a valid binary search tree?

Question

Decide whether a binary tree is a binary search tree: for every node, all values in its left subtree are strictly smaller than it and all values in its right subtree are strictly larger. Duplicates are not allowed.

Input[8, 4, 12, 2, 9, 10, 14]
Outputfalse
Why9 sits in 8's left subtree but is bigger than 8
Think first: why isn't checking each node against its children enough?

In the example, 9 is a fine right child of 4, yet it breaks the rule for 8, two levels up. Each node must fall inside a range set by all its ancestors. Pass that range down: going left, the parent's value becomes the new upper bound; going right, it becomes the new lower bound. The root starts with (−∞, ∞).

Each stack frame shows the node and its allowed range (lo, hi). Red ring = the value falls outside its range.

Time O(n)Space O(h)Comparing only with children: wrong answer
Correctness

Why every node is handled once, in the right order

Induction

Assume dfs handles every node of any tree smaller than the current one correctly. The left and right subtrees are smaller, so the two calls cover them, and the node itself is handled by the one line of work. The empty tree is the base case. So every node is visited exactly once: O(n) time.

The stack

At any moment the call stack holds exactly the path from the root to the current node: each frame is paused, waiting for a child to finish. So the extra memory is the height h, which is about log₂ n for a balanced tree and n for a chain.

Inorder sorts a BST

Inorder lists the left subtree, then the node, then the right subtree. In a search tree the left values are all smaller and the right ones all larger, and by induction each subtree is listed in sorted order. So the whole list is sorted.

BFS goes by depth

The queue always holds nodes from at most two neighbouring depths d and d + 1, the d ones in front. A node at depth d only adds children at depth d + 1 to the back, so all of depth d leaves the queue before any of depth d + 1. That is why the first time BFS reaches something is along a shortest path from the root.

In an interview

Say which direction the information flows. "The answer needs both children's results, so postorder and return a value" or "each node needs a bound from above, so pass it down." Then name the base case and the stack depth.
