Fast and Slow Pointers

Send two pointers down the same linked list, one moving one node per step and the other moving two. When the fast one reaches the end, the slow one is halfway. If there is no end because the list loops, the fast one laps the slow one and they land on the same node. Both facts come with O(1) extra memory.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, from first principles

Two speeds turn distance into information

A singly linked list only lets you walk forward, one next at a time. You don't know its length, and you can't jump to the middle. The obvious fixes cost memory: copy the nodes into an array to find the middle, or keep a set of visited nodes to spot a loop. Both are O(n) extra space.

Run two walkers instead. After k steps the slow one has moved k nodes and the fast one 2k. That fixed ratio is the whole trick. If the list ends, the fast pointer gets there when the slow one is at the halfway mark. If the list loops, both end up circling, and the fast one gains exactly one node per step, so the gap between them shrinks by one each step until it hits zero. They must meet; the fast one can't jump over the slow one.

Recognizing the pattern

Signals in the problem statement

  • The input is a linked list (or something you can only step through with a "next" function) and you don't know its length.
  • The question asks about the middle, or a point a fixed fraction of the way along, in one pass.
  • It asks whether a sequence loops, repeats or "eventually reaches" something, or where a loop begins.
  • It demands O(1) extra memory, which rules out a visited set or copying into an array.

Counter-signal: "the k-th node from the end" also uses two pointers, but they move at the same speed with a head start of k. That's a fixed gap, not two speeds. And if you can afford O(n) memory and want the simplest code, a hash set of visited nodes detects a cycle too.

Template

The skeleton you adapt

slow = fast = head
while fast and fast.next:        # fast needs two more nodes to move
    slow = slow.next             # 1 step
    fast = fast.next.next        # 2 steps
    if slow is fast:             # only possible inside a cycle
        return "cycle"
return slow                      # fast hit the end: slow is the middle

Two details decide most bugs. The loop condition must check fast and fast.next, or the double step crashes on the last node. And compare nodes by identity (is), not by value: two different nodes can hold the same number.

Problem 1 · Find a position

Middle of a linked list

Question

Given the head of a singly linked list, return its middle node. If the list has an even number of nodes there are two middles; return the second one. Walk the list only once.

Input3 → 8 → 1 → 6 → 4
Outputthe node holding 1 (index 2)
Even length3 → 8 → 1 → 6 gives 1 (index 2)
Think first: where is slow when fast runs out?

After k steps slow is at index k and fast at index 2k. The loop stops when fast can't take two more steps, which happens when 2k is the last index (odd length) or one past it (even length). Either way k is n ÷ 2 rounded down, the second middle.

Time O(n)Space O(1)Count first, then walk again: two passes
Problem 2 · Detect a loop

Does the list have a cycle?

Question

Given the head of a linked list, return true if following next pointers ever brings you back to a node you've already visited, and false if you reach the end. Use constant extra memory.

Input2 → 7 → 4 → 9 → 5 → 1, last node links back to index 2
Outputtrue

In the visualizer, "tail links to" is the index the last node points back to, or −1 for no loop.

Think first: why can't fast skip over slow?

Once both are in the loop, measure how far fast is behind slow along the loop. Each step slow adds 1 and fast adds 2, so that gap drops by exactly 1. A gap that drops by 1 each step reaches 0; it can't go from 1 to −1.

Time O(n)Space O(1)Visited set: O(n) space
Problem 3 · Detect a loop, then locate it

Where does the cycle begin?

Question

Given the head of a linked list, return the first node of its cycle (the node the tail points back to), or null if there is no cycle. Don't modify the list, and use constant extra memory.

Input2 → 7 → 4 → 9 → 5 → 1, tail links to index 2
Outputthe node holding 4 (index 2)
Think first: what do you know at the meeting point?

Let a be the distance from the head to the loop start and b from the loop start to the meeting point. Fast walked twice as far as slow, and the extra distance is a whole number of laps. That forces a to equal "some laps minus b". So a pointer from the head and a pointer from the meeting point, both moving one step at a time, arrive at the loop start together.

Time O(n)Space O(1)Visited set: O(n) space
Problem 4 · Implicit list

Is it a happy number?

Question

Start from a positive whole number. Replace it with the sum of the squares of its digits, and keep going. If you eventually reach 1, the number is happy. Otherwise the values repeat forever without reaching 1. Decide which, without storing the values you've seen.

Input19
Outputtrue: 19 → 82 → 68 → 100 → 1
Input2
Outputfalse: it falls into 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4
Think first: where is the linked list?

Each number has exactly one "next" number, so the values form a linked list that must eventually repeat (the values quickly drop below a few hundred). 1 maps to itself, a cycle of length one. Run slow and fast on the values; when they meet, check whether the meeting value is 1.

Correctness

Why they meet, and why the second walk finds the start

No cycle

Fast moves two nodes per step, so it reaches the end after about n/2 steps, and the loop stops. Slow has moved half as far: the middle.

Meeting

Once slow enters the loop, fast is somewhere in it, d nodes behind (d less than the loop length c). Each step closes the gap by exactly 1, so they meet within c steps. Total time is O(n).

Loop start

Let a = head to loop start, b = loop start to meeting point. Slow walked a + b; fast walked 2(a + b), which is a + b plus k full laps. So a + b = kc, which means a = kc − b. Walking a steps from the meeting point is k laps minus b: you land exactly on the loop start, at the same moment as a pointer that walked a steps from the head.

In an interview

State the gap argument for meeting ("closes by one per step, can't skip") and write out a = kc − b for the start. Then mention that the same code works on any function x → f(x), not just node pointers.

2(a + b) = a + b + k·c ⇒ a = k·c − b
