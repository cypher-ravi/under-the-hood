Fast and Slow Pointers

Send two runners down a linked list, one taking one step at a time and the other two. If the list ends, the slow one is at the middle when the fast one finishes; if the list loops, the fast one laps the slow one and they meet.

In 30 seconds
  • What: two pointers on the same list, slow moving 1 node per step and fast moving 2.
  • When: a linked list (or any "next" rule) where you need the middle, or need to know whether it loops and where.
  • Why it's fast: one pass, O(n) time, and only two pointers of memory. No array copy, no set of visited nodes.
  • The one thing to get right: the loop condition fast and fast.next, so the double step never steps off a null.

Pattern-first structure inspired by Codeintuition's curriculum. Problems, explanations and visualizations on this page are our own.

The idea, by example

Two runners on a looping track

A linked list only lets you walk forward, one next at a time. You don't know its length. Here is a list of seven nodes whose last node points back to node 2, so it never ends.

Put slow (S) and fast (F) on the head. Each step, S moves one node and F moves two. Watch the gap between them once both are in the loop. The S and F columns are node indices, the small numbers under each node.

StepSFWhat it tells us
000Both start at the head.
112F pulls ahead and enters the loop.
224S enters the loop too. F is 3 nodes behind S, going round.
336F gains one node per step. Now 2 behind.
443F wrapped round to node 3. 1 behind.
555Gap 0. Same node: there's a loop.

Now take the loop away. F reaches the end after about n/2 steps, and S, having gone half as far, is standing on the middle node. Same code, a different fact.

Fast gains exactly one node per step. A gap that shrinks by one can't jump over zero, so in a loop they must meet. Without a loop, fast hits the end when slow is halfway.

Recognizing the pattern

Signals in the problem statement

Reach for fast and slow pointers when you see one or more of these:

  • The input is a linked list, or something you can only step through with a "next" rule, and you don't know its length.
  • The question asks for the middle, or a point a fixed fraction of the way along, in one pass.
  • It asks whether a sequence loops, repeats or "eventually reaches" something, or where a loop begins.
  • It demands O(1) extra memory, which rules out a visited set or copying into an array.

When not to: "the k-th node from the end" also uses two pointers, but at the same speed with a head start of k. That's a fixed gap, not two speeds. And if memory is no concern, a set of visited nodes finds a loop with simpler code.

Template

The skeleton you adapt

slow = fast = head
while fast and fast.next:
    slow = slow.next       # 1 step
    fast = fast.next.next  # 2 steps
    if slow is fast:       # a loop
        return "cycle"
return slow  # no loop: the middle

To adapt it to a new problem, answer three questions:

  1. What is "next"? A node's next pointer, or a rule like "sum of squared digits" that turns one value into the next.
  2. When does the race stop? Fast runs out (no loop), or the two land on the same node (a loop).
  3. What do you read off at the end? Slow's position (the middle), true/false (is there a loop), or a second walk to find where the loop starts.
Problem 1 · Find a position

Middle of a linked list

Question

Given the head of a singly linked list, return its middle node. If the list has an even number of nodes there are two middles; return the second one. Walk the list only once.

Input3 → 8 → 1 → 6 → 4
Outputthe node holding 1 (index 2)
Even length3 → 8 → 1 → 6 gives 1 (index 2)

If fast has covered the whole list, how far has slow gone?

The obvious way

Walk the list once to count n nodes, then walk again n/2 steps. That's two passes, or an O(n) array if you copy the nodes to jump straight to the middle.

Key insight

After k steps, slow is at index k and fast at index 2k. Fast runs out when 2k reaches the last index (odd length) or one past it (even length). Either way slow sits at n ÷ 2 rounded down, which is the second middle.

The plan

  1. Put slow and fast on the head.
  2. While fast and fast.next both exist, move slow one node and fast two.
  3. When the loop stops, return slow.

Watch it run

S (blue) is slow and F (amber) is fast; the number under each node is its index. Try the even-length preset to see which middle you get.

Time O(n)Space O(1)Count, then walk again: two passes

Writing while fast.next. On an even-length list fast becomes null, and null.next crashes. Check fast first.

Problem 2 · Detect a loop

Does the list have a cycle?

Question

Given the head of a linked list, return true if following next pointers ever brings you back to a node you've already visited, and false if you reach the end. Use constant extra memory.

Input2 → 7 → 4 → 9 → 5 → 1, last node links back to index 2
Outputtrue

Once both pointers are going round the loop, why can't fast jump over slow?

The obvious way

Keep a set of every node you've visited. If you reach a node already in the set, there's a loop. It works in O(n) time but needs O(n) extra memory.

Key insight

Inside the loop, measure how far fast is behind slow. Each step slow adds 1 and fast adds 2, so the gap drops by exactly 1. A gap that drops by 1 each step reaches 0; it can't go from 1 to −1. So they always meet.

The plan

  1. Put slow and fast on the head.
  2. While fast and fast.next exist, move slow one node and fast two.
  3. After each move, if they're on the same node, return true.
  4. If fast runs off the end, return false.

Watch it run

The red arrow under the list is the tail's link back. "Tail links to" is the index it points to, or −1 for no loop. Once both pointers are in the loop, the "gap in loop" counter drops by one each step.

Time O(n)Space O(1)Visited set: O(n) space

Comparing values instead of nodes. Two different nodes can hold the same number; use is (same node), not == on the values.

Problem 3 · Detect a loop, then locate it

Where does the cycle begin?

Question

Given the head of a linked list, return the first node of its cycle (the node the tail points back to), or null if there is no cycle. Don't modify the list, and use constant extra memory.

Input2 → 7 → 4 → 9 → 5 → 1, tail links to index 2
Outputthe node holding 4 (index 2)

Slow and fast have just met. What do you know about how far each has walked?

The obvious way

Walk with a visited set; the first node you see twice is the loop start. Easy, but O(n) extra memory.

Key insight

Call a the distance from the head to the loop start, and b from the loop start to the meeting point. Fast walked twice as far as slow, and the extra is whole laps. That makes a equal to "some laps minus b". So one pointer from the head and one from the meeting point, both at speed 1, reach the loop start together.

The plan

  1. Run Problem 2. If fast runs off the end, return null.
  2. When they meet, put a new pointer p on the head. Leave slow at the meeting point.
  3. Move p and slow one node at a time until they're on the same node.
  4. That node is the loop start. Return it.

Watch it run

Phase 1 is the race from Problem 2; the amber-outlined node is where they meet. In phase 2, H is p walking from the head and S is slow walking on from the meeting point. Compare the "Long tail" and "Short tail" presets.

Time O(n)Space O(1)Visited set: O(n) space

Keeping a double step in phase 2. The second walk only works if both pointers move one node at a time.

Problem 4 · Hidden list

Is it a happy number?

Question

Start from a positive whole number. Replace it with the sum of the squares of its digits, and keep going. If you eventually reach 1, the number is happy. Otherwise the values repeat forever without reaching 1. Decide which, without storing the values you've seen.

Input19
Outputtrue: 19 → 82 → 68 → 100 → 1
Input2
Outputfalse: it falls into 4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4

There are no nodes here. Where is the linked list?

The obvious way

Keep a set of every value you've produced. Stop when you hit 1 (happy) or a value you've seen before (a loop). It works, but the set is extra memory.

Key insight

Each number has exactly one "next" number, so the values form a linked list. The values soon drop below a few hundred, so the list must repeat. 1 maps to itself, a loop of length one. Run slow and fast on the values; when they stop, check whether fast is on 1.

The plan

  1. Write step(x): the sum of the squares of x's digits.
  2. Start slow at n and fast at step(n), one step ahead.
  3. While fast isn't 1 and slow ≠ fast: slow takes one step, fast takes two.
  4. Return whether fast is 1.

Watch it run

Each circle is a distinct value in the order step() produces it, and the red arrow shows where the values start repeating. The real algorithm never builds this list; it's drawn so you can see the shape.

Time O(log n) per step, few stepsSpace O(1)Set of seen values: extra memory

Starting slow and fast both at n with the check slow != fast. They're equal before the first move, so the loop never runs.

Correctness

Why they meet, and why the second walk finds the start

Three plain sentences, then one line of algebra:

Always true

After k steps, slow has walked k nodes and fast has walked 2k. Fast is never behind slow on the way in.

Each step

Once both are in the loop, fast is d nodes behind slow, with d less than the loop length c. Each step closes the gap by exactly 1, so they meet within c steps.

It ends

With no loop, fast reaches the end after about n/2 steps, and slow is at the middle. With a loop, they meet within one lap. Either way O(n).

Loop start

Slow walked a + b. Fast walked 2(a + b), which is a + b plus k full laps. So a = kc − b: walking a steps from the meeting point lands exactly on the loop start, the same moment a pointer from the head gets there.

2(a + b) = a + b + k·c ⇒ a = k·c − b

In an interview: state the gap argument ("closes by one per step, can't skip") and write out a = kc − b for the start. Then mention that the same code works on any rule x → f(x), not just node pointers.

Recap

Cheat sheet

Middle

1 step and 2 steps. When fast runs out, slow is the middle.

Has a loop?

Same race. Same node → true. Fast hits null → false.

Loop start

After they meet, p from head and slow from the meeting point, both speed 1.

Happy number

step(x) is "next". Race on values; happy if fast reaches 1.
